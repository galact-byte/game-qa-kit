# 游戏控制插件开发

目标是通过统一指令执行正常游戏交互，同时保留操作后证据。接口与实验命令见本仓库 `docs/BACKGROUND-CONTROL.md`；现有实现见 `gameqakit/control.py` 和 `plugins/`。

## 先核对边界

1. 读取项目约定、当前进度和存档账本。确认允许的测试副本、槽位、禁止触碰的数据及还原方式；不凭复制游戏目录认定存档已隔离。
2. 只读识别运行时、版本、输入系统和现有插件。MV/MZ 可复用 JavaScript 家族实现，VX Ace 使用独立 RGSS3/Ruby；XP/VX、Unity 和其他引擎分别验证。定制 RGSS 脚本须定位真正执行的 `rgss_main` 入口，不能仅按名为 Main 的段落插入。
3. 优先复用已验证插件。已有 BepInEx、能截图或进程存活不代表输入可用。Unity 实现集中于 `plugins/unity/`，先读 README 的运行时／输入后端矩阵，不索取不存在的用户插件。旧 Input 使用托管调用点／委托，新 Input System 使用虚拟设备／事件，IL2CPP 使用独立加载入口，Rewired 按真实映射适配；不能混用构建或把一个组合通过扩大为全部支持。HSP 先读 `plugins/hsp/README.md`：当前只实证 Windows x86／官方 HSP 3.7 与八星帝外置字节码的标题／读取菜单，原 EXE 内嵌脚本不自动读取修改后的外置脚本。

## 最小验证顺序

- 先用已有 SDK 空白工程或已批准、已备份且明确写入位置的隔离副本。不要往原游戏直接注入，不自动安装运行时、模型或改变安全配置。`DesktopProcess` 先挂起创建子进程，写好会话绑定后必须调用 `run()`，再等心跳；不能将尚未恢复的进程误判为引擎卡死。
- Unity 必须通过 `DesktopProcess` 绑定实际独立桌面；新连接先写 JSON/INI，再恢复。先用 `tests/unity_smoke.py` 的独立产品标识空白场景验证；商业验收使用已核查保存路径的完整副本，记录原文件、原 PlayerPrefs、原 persistentDataPath 前后校验与相对保存目录备份。旧 Unity 的启动对话框和 CLR 版本先核对，不把加载失败等同于输入不兼容。暂停验收须同时有 connected=true、paused=true、held=[]；菜单可能在同一场景切换，必须读回截图，不能只看场景名。开场／地图对话可能锁住移动，先用正常输入推进并确认操作开放，再核对真实位移和画面；不只延长等待，也不绕过游戏流程。
- HSP 使用 `tests/hsp_smoke.py` 验证 HPI3 getkey、stick 直接读取、窗口鼠标缓存和原生控件；await／wait、非激活态、暂停取消按钮不误点击及桌面不符拒绝分别核对。桥更新计数不等于渲染帧率；商业控件类型未经证实，不借空白工程的原生按钮结论代认。
- DuckStation 先读 `plugins/duckstation/README.md`，准备入口与 DLL 都检查完整 EXE SHA-256。在独立便携副本用原生帧号／单步计时与数字手柄回读验证消费，SDL 轮询回调不等于游戏帧。`tests/duckstation_smoke.py --safety --mcp` 验证正式协议与文件路径启动的 MCP；超过内联上限的截图核对返回路径与哈希，不放宽上限。固定启动等待仍需读图确认。原配置、镜像和进度只读，空白记忆卡留任务目录；开局屋内移动、正常保存／读取和重启读测试卡已有短程实测，不能扩大为全流程。菜单键用 `press(button="square",frames=12)`，先核对状态 `buttons` 声明；不要用 Start／`shift` 代替。动作松键后黑场只在原 3 秒内每 30 帧观察，到期仍停，显式恢复不能追认失败；未知结果先按原编号查，不盲重发。桥梁首战已有正常输入实测：走格、战斗命令、双方回合、伤害／升级、战后对白及离桥返回世界地图；证据见 `<PS1验证目录>/battle-retest/战斗验证.md`，不能扩大为任意战斗或全流程。实体手柄验证按当前需求跳过，只保留接口；音频、换盘及其他构建分别验证。
- Wolf 先读 `plugins/wolf/README.md`：仅支持固定 EXE 哈希的官方 Windows x86 范例。`prepare.py` 不带原 Save／SaveData；DLL／加载器只放入新建的独立桌面副本。`tests/wolf_smoke.py --safety --mcp` 验安全，`--mcp-steps` 验真实 MCP 输入。完整循环才计帧，多次 DirectInput 轮询只证明消费；普通动作释放后另有两轮观察。暂停须等 connected、paused、held 为空及 `at_frame_boundary=true` 后再比较帧／轮询数。菜单需等动画，移动松键后走完当前格再看位置稳定。当前只实证标题、正常对话、左右位移与菜单，其他构建、存读档及战斗另验；写入守卫不当作完整沙箱，超时仍按原编号查询，不抢前台。
- 分别证明失焦逻辑更新、操作后新画面、双向输入隔离。独立 Win32 Desktop 不是虚拟机，也不隔离 AppData/注册表；没有把最小化测过就不声称支持。
- 主程序只使用共用动作和能力发现，插件独立翻译输入，不互相依赖。按游戏线程执行正常输入，不直接改任务、剧情、位置或场景结果冒充通过。
- 先补会因行为缺失失败的测试，再最小实现。命令有会话/目标约束和唯一编号；重复命令不重复执行，未知结果先按原编号查回执。
- 验证动作后的帧、有效 PNG、可读状态与真实画面一致。SDK 地形阻挡时，转向不是位移；把样本限制记录下来。定制游戏可能重写 `Graphics.frame_count` 等接口并延迟初始化；桥应使用自身更新计数，不在入口前依赖尚未准备好的游戏诊断状态。
- 验证暂停优先于排队动作，释放所有按键；过期租约、断线、截图失败、旧会话暂停和迟到回执均不能引发下一次输入。`historical=true` 不能指导当前动作。
- 暂停请求后确认 `paused=true` 且 `held=[]`；人工接管后的恢复需明确授权。后台通路失败不退回真实鼠标/键盘，不强制前台。

## 交付

运行受影响自动测试和真实隔离工程，记录确切版本、帧、截图、失败批次与未验证范围。安全拒绝后应核对是否消费输入，只有回执明确未消费且条件已恢复时才可用新编号重试；后续通过不能代替原失败原因的证明，不放宽租约阈值。回收测试进程和游戏副本，只保留必要证据与恢复备份。更新路线、变更记录及被测游戏约定的同步记录。需要新安装、原游戏注入或无法确认存档写入位置时，交付具体阻碍和最小下一步；不要编写未验证的万能适配教程。
