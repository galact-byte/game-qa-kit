# Godot macOS arm64 受管验证

当前已完成固定自写组件的受管原生验收，默认仍不开放 macOS 游戏控制。组件测量批次 `45028494838` 的实际摘要已登记；复验批次 [`45043961784`](https://github.com/galact-byte/game-qa-kit/actions/runs/45043961784) 在提交 `8127fa7` 上完成源码 MCP 八类场景与冻结包两类场景。独立解码 84 张原始 PNG，核对动作回执摘要、实际位置 `60 → 100 → 60`、16 次完全遮挡检查共 1,372,160 像素及进程回收记录；正常停止两形态的持续焦点记录均未激活目标或改变前台。该结论仅覆盖本批固定运行时与自写场景，不外推商业 PCK、其他构建、长期稳定性或真人键鼠并发。

历史失败保留：批次 `45031143035` 已完成源码场景，冻结包准备被链接路径守卫拒绝；修正后 `45040306222` 在源码 worker 中断验收读早了监督器状态，冻结包未开始。验收脚本现共用原有 8 秒预算等待内层 PID 消失及外层监督器完成收尾，产品回收逻辑未改。成功复验不追认历史失败。登记组件的版本、架构、固定上游、补丁、自写 PCK、来源及许可文件由原生验收在启动前核对实际摘要；Windows 回归不能替代 macOS 原生检查。

## 接入范围

仅支持验证 macOS 14+ Apple Silicon、固定 Godot 4.5.1 no-focus 构建与仓库自写 PCK。`GAMEQA_MACOS_MANAGED_VALIDATION=1` 只打开有限工具入口；检查、准备及启动仍要求源码登记的运行时、样本、桥和来源文件摘要匹配。不能用组件目录自带的清单提供信任摘要。

MCP 复用 `game_inspect`、`game_prepare`、`game_start`、绑定、`control_*`、解绑和 `game_stop`。桌面键鼠、任意外部进程停止、其他引擎、商业 PCK、Intel macOS、真实游戏与长期稳定性均不在此次验收范围内。

## 生命周期与证据

- `gameqakit/macos_process.py` 通过监督器、等待门与创建者管道管理本会话的进程组。先取得 PID 和启动身份，再建立连接及启动前焦点监视，最后允许目标 exec。停止权由活着的创建者持有，不从磁盘 PID 恢复。macOS 对只剩僵尸的进程组可能返回 EPERM；只有系统查询成功且组内全部为僵尸时接受，仍有活进程、空结果或查询失败均报错。
- `gameqakit/process_identity.py` 通过已有 Swift 辅助程序调用 libproc；身份查询不依赖屏幕录制权限。连接同时核对 PID、启动时间、可执行路径及会话标识。
- `gameqakit/macos_focus.py` 及 Swift 监视器从目标 exec 前持续记录前台与激活事件。目标激活、前台变化、陈旧记录或监视器退出都会停止输入；不恢复前台掩盖变化。
- Godot 会话使用独立用户及临时目录；桥内绘制、回执和原有守卫继续生效。数据目录隔离不构成文件系统沙箱。3 秒截图和松键确认、原租约与 15 秒产品启动循环不延长。

## 两步组件验证

独立工作流 `.github/workflows/godot-macos-managed.yml` 以固定上游 `f62fdbde15035c5576dad93e586201f4d41ef0cb` 与 `tools/godot-no-focus.patch` 构建组件。空 `component_run_id` 只构建和测量，不启动游戏场景。

构建结果记录实际版本、架构、运行时及自写 PCK 摘要，附源码清单、补丁、Godot `LICENSE.txt` 和 `COPYRIGHT.txt`。检查这些实际产物后，再将摘要登记到 `plugins/godot/macos-arm64-component.json`，不能沿用旧构建摘要。

登记后以原构建运行号作为 `component_run_id` 下载同一份组件，不再编译运行时。先通过真实 MCP 执行源码验收，再构建冻结 `.app` 并验证其 MCP、worker 和监督器内部入口。各阶段失败即停，保留失败证据，不自动重复原生批次。除完整工件外，`godot-macos-review-<run>-<attempt>` 单独保存原始 PNG、场景结果、焦点与回收记录，避免复核时重复下载运行时副本。

PyInstaller 在 macOS App 内以符号链接组织部分资源；仓库内置桥脚本从解析后的物理资源路径复制，并照常核对摘要。此修正不适用于用户选择的样本、运行时或目标目录，这些路径仍拒绝链接。批次 `45031143035` 的冻结准备失败保留，需用修正后的冻结包重新验证。

原生验收包括：

1. 准备去重、启动前取消、组件被改拒绝及无持键暂停首图。
2. 遮挡像素、遮挡中新观察、正常移动与等待、回执去重及原始 PNG。
3. 动作进行中暂停、租约自然到期松键、解绑后拒绝输入、重新绑定保持暂停。
4. 观察者无停止权；正常停止、创建者 EOF／异常退出、worker 退出、目标先退出和焦点监视失效的进程回收。
5. 固定源样本摘要不变、源码与冻结形态的焦点和进程退出证据。

源码验收覆盖上述全部场景；冻结包验证正常停止（含动作中暂停、失租及解绑）与创建者强制退出两类，未逐项重复源码侧的取消、篡改、焦点监视失效、目标退出、worker 中断和创建者 EOF。批次 `45043961784` 的 15 项原生进程契约检查通过，云端记录清单后回收 634,475,032 字节可再生产物。独立复核摘要与原始图保留在 `<Godot macOS受管验证目录>/native-45043961784/`。

故障场景保留实际失败语义：篡改为 `failed`，焦点监视失效／目标退出可为 `cleanup_failed`；worker 中断为 `interrupted_unverified`，不声称已确认松键，仍撤销后续停止权限。创建者被强制结束后，末份状态可能仍是 `ready_paused`，进程回收由独立 PID／进程组记录证明，不能以过期状态代替回收证据。

原始 MCP 请求／响应、PNG、状态、来源清单及清理记录归档到 `<Godot macOS受管验证目录>/`。成功批次需另行独立解码图片并核对结果，日志中的 `ok` 不能替代可视证据。构建树和临时运行时在记录清单后清理，失败证据保留。
