# Linux X11 产品采集接入设计

## 状态与范围

此文为待审阅的接入设计，尚未启用 Linux 产品采集。已有独立探针证明 Ubuntu 22.04 x64、Xvfb、Composite 0.4 上自写 CPU 与 Mesa llvmpipe 软件 OpenGL 窗口可在完全遮挡及改尺寸后持续取得新图；八类生命周期检查通过，并实际复现窗口 ID 被其他进程复用。下载后完成 141 项独立核对、34 张目标 PNG 计数一致。这不代表真实桌面、物理 GPU 游戏或 arm64 已支持。原始结果见 [X11 探针](X11-CAPTURE-PROBE.md)。

本阶段将该能力接入现有配置、窗口选择、采集会话、观察、人工标记与证据复核。不添加输入后端，不启动商业游戏，不改存档，不下载系统组件。Wayland 独立验收，不通过 XWayland 或整屏裁切冒充窗口源支持。

## 推荐方案与取舍

沿用 macOS 已有的隔离模式：产品父进程复用公共采集会话，独立 Python 辅助进程通过 ctypes 调用系统 libX11 与 libXcomposite，使用有界二进制帧协议返回单窗口 PNG；源码模式运行包内模块，冻结模式由同一便携程序的内部入口执行。这样无需额外 Python 包或另编译 C 程序，同时将 X 连接中断、服务端错误与潜在原生崩溃限制在可回收子进程内。

不采用 Qt 自带窗口取图：既有源码核查未见它使用 XComposite 命名 pixmap，不能据此保证遮挡新图。不让产品 GUI 线程直接执行 ctypes/Xlib 调用：X I/O 失败可能结束调用进程，无法保证 GUI 和公共 MCP 可继续使用。系统库缺失时报告具体缺失项，保持其他公共功能可用；不自动安装或修改 X 访问控制。

正式辅助程序、内部入口与冻结打包属于架构变更，实施前需要审阅本设计并取得明确批准。当前只准备设计与验收清单，不因路线图的一般推进授权推断该具体架构已获批准。

## 模块边界

- `gameqakit/x11_native.py`：仅在辅助进程导入；声明 ctypes ABI、查询树和属性、绑定身份、命名 pixmap、读取并转换像素、释放服务器资源。不得调用焦点、窗口置顶或输入 API。
- `gameqakit/x11_helper.py`：辅助进程入口、操作分派和有界协议；所有 Xlib 交互串行执行。设置错误处理，区分窗口消失、重定向冲突、连接失败与协议错误；无法恢复时终止该辅助进程。
- `gameqakit/x11_capture.py`：产品平台后端、窗口筛选与公共采集会话适配；持有辅助进程、期限、取消和回收。PNG 解码、像素预算、身份复核沿用公共约束。
- 平台分派与打包：仅在 Linux、已确认 X11 会话且可连接目标 DISPLAY 时启用；冻结清单带齐内部模块与已有图像依赖。不得在导入平台信息时加载 Xlib 或要求桌面可用。

拟复用 macOS 的帧协议及父进程有界管道实现，但先核查可直接抽出的小型公共模块；不为少量共用代码重写既有 Windows 后端。协议版本、PNG 上限、JSON 上限和超时行为保持现值。

## 窗口身份与选择

候选来自 X 窗口树与 EWMH/ICCCM 属性。窗口 ID 本身不足以绑定来源；至少记录 DISPLAY、XID、进程 ID、`/proc/<pid>/stat` 的启动 tick、`/proc/<pid>/exe` 解析后的路径及本次连接标识。读取 stat 时按最后一个右括号识别 comm 字段边界，不能直接按空格切分包含空格的进程名称。

无本机 PID、远端主机属性、不属于当前 UID、无法可靠读取进程身份的窗口默认不作为可绑定目标，并给出原因。窗口标题和 WM_CLASS 仅用于展示和筛选，不作为安全身份。每次截图前后重新查询 X 属性、进程启动时间、路径和尺寸；变化则停止并要求重新选择。窗口 ID 重用、PID 重用、退出期间的读取竞态必须有回归。

配置保存稳定的进程/标题偏好；运行中的短暂窗口身份不作为下次启动自动可信的长期绑定。多候选时要求用户选择，不能猜第一个。

## 取图与资源生命周期

仅使用 XComposite 命名 pixmap，不从根窗口裁切目标。每次尺寸或映射代次改变后释放旧 pixmap 并重新绑定，读取几何后检查宽高、总像素与步长再分配内存；根据真实 `XImage` 的 byte_order、bits_per_pixel、bytes_per_line、RGB mask 转换，不假定 BGRX32 或连续行。

重定向仅限所选目标，模式采用自动重定向。启动时记录是否由本辅助进程建立重定向，结束时只撤销本进程拥有的资源；不得撤销窗口管理器或其他客户端的重定向。服务端拒绝、已存在的独占重定向及不支持的图像布局均明确失败，不改桌面设置兜底。

主流程：连接并确认 Composite → 绑定身份与重定向 → 命名 pixmap → 同步服务端状态 → 有界取图 → 再校验来源 → 发布帧。关闭顺序：停止新请求 → 取消等待 → 释放 XImage 和 pixmap → 撤销自己建立的重定向 → 关闭 X 连接 → 回收辅助进程。各步骤可重复关闭；父进程异常退出时辅助进程读到 EOF 后清理，X 连接关闭作为服务器侧资源的最终回收保证。

连续观察与人工截图/标记必须在同一目标上可并行调用，并通过真实多进程验证资源互不撤销。若 X server/窗口管理器不允许该组合，保留失败证据，再决定是否需要共享采集所有者；不得未经验证默认照搬 macOS 的生命周期锁。

## 失败语义与期限

- 无 DISPLAY、认证失败、X 连接中断、缺库/扩展：明确告知环境或权限问题，不发起安装、xhost 放行或其他认证变更。
- 目标关闭、来源重用、最小化/取消映射、尺寸不合法：结束当前观察并清除旧帧；不以旧图继续汇报成功。
- 超时与取消：沿用现有 3 秒截图期限；到期结束辅助进程并回收，停止观察不等待无限 Xlib I/O。
- 黑白画面：沿用现有守卫；纯黑首图仍零输入停止，冻结反例仍必须被连续增长判据拒绝。
- Xlib 错误和 I/O 中断：保留内部错误及阶段，GUI/MCP 报告有限可读错误；不向共享终端持续喷日志。

## 验收顺序

1. 单元回归先红后绿：平台分派不导入 Xlib、窗口/PID 重用、stat 名称解析、错误像素布局、内存上限、超时、取消、关闭幂等及异常回收。
2. 复用已存在的 Ubuntu 22.04 x64/Xvfb 环境，自写目标/遮挡/产品为独立进程；可见、完全遮挡、冻结反例、遮挡中改尺寸、窗口关闭、辅助进程退出、X server 中断逐项执行。
3. 通过真实 MCP 执行配置、绑定、持续观察、状态、人工标记、证据列表与复核；观察和人工截图同时运行，不抢前台，不发送输入。
4. 核对 PNG 实际计数、四角标记、文件摘要、来源字段和去重归档。根窗口图仅作完整遮挡证明；普通目标截图必须来自 pixmap。原始失败与成功证据分别保存。
5. 冻结便携包执行同一套产品链，确认无需系统 Python；源码结果不能代替冻结产物。
6. 后续再取得真实窗口管理器与 GPU 绘制自写样本、Linux arm64 及普通授权桌面。未验前支持表限定为实测组合，不宣称任意 Linux 游戏。

首次环境为已有 CI 组件，不额外 apt/pip 安装。若镜像缺失依赖，先给出精确缺项及已有环境差异，再按安装批准边界处理。

## 回退与交付

后端通过之前保持 Linux 的产品采集入口关闭；回退仅撤销平台分派与随包内部入口，不影响配置、存档快照、已有证据或 Windows/macOS 后端。所有证据保存在任务专用目录，仓库文档使用通用占位路径。交付时同步路线图、平台支持表、操作说明、来源许可与变更记录。
