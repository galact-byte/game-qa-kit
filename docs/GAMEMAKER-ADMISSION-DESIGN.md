# GameMaker 自写 YYC 受管入口设计

日期：2026-11-19。状态：已获批准并实施固定自写 YYC 受管桥；当前验收结果与边界见[预检记录](GAMEMAKER-PREFLIGHT.md)。

## 目标与已验证依据

让统一 MCP 在独立桌面启动固定自写 YYC 场景，执行右移／等待，并取得正常输入查询消费、释放和画面证据。首版只接官方组件 2026.0.0.23 编译、通过本机 VS 2022 v143 构建的登记 x64 自写程序；不接商业程序或任意 GameMaker 工程。

[预检记录](GAMEMAKER-PREFLIGHT.md)已证明：VM 和 YYC 自写场景失焦更新与生产取图成立；独立 YYC 生成源码副本在 Step 开始处映射 `_IO_KeyDown[39]`，正常 `YYGML_keyboard_check(39)` 消费后移动，900 ms 绝对期限到期后停止。未加入映射的同场景有预期失败批次；原始生成源码未改。

实验只证明固定版本、固定自写事件的一种查询。它没有正式身份、命令编号、消费回执或生命周期保护，不能直接接入 MCP。截图展示的逻辑步数用于证明活性，不直接作为统一接口的 `frames`。

## 推荐方案与替代路线

首版使用自有 C++ 源码桥，在自写场景生成／构建阶段静态链接到目标，并在固定 Step 事件的输入查询前执行。准备器只复制已登记的构建成品，不在用户运行时修改 EXE、扫描未知内存或执行编译器。产品侧复用 `DurationSession`、`Supervisor`、`ManagedCapture`、`DesktopProcess` 和协议 2；单动作单位为 `duration_ms`。

这是在自写 YYC 样本内建立有限受管入口的方案，不能迁移到没有源码的商业 EXE。选它是因为本机已具有输入与画面证据，且不需要新增 DLL 注入器或第三方加载器。已核对的 YYToolkit 仍是无源码目标的候选，其本机兼容性、YYC 调用边界与 AGPL-3.0 交付义务尚未验；本设计不授权下载、集成或分发它。VM 输入也不由本设计推断为可用。

## 构建与组件边界

- 将自有 GML 样本、C++ 桥源码、可复跑构建脚本和组件摘要登记放在 `plugins/gamemaker/`；官方 IDE、Igor、Runner 库、生成的引擎头文件和编译缓存留在本地，不入源码库。
- 使用匹配的官方组件生成 YYC 工程，仅在自写 Step 固定入口加入桥调用；构建脚本必须确认预期入口唯一、生成结构和组件匹配，再使用本机 v143 工具链。结构不符即失败，不猜偏移或放宽摘要。
- 输入查询之后由自写事件回报本次普通采样的结果，提供按下或释放的消费证据。不能用桥写入布尔值成功代替普通查询消费，不能由桥设置角色坐标或执行场景结果。
- 构建后登记完整 EXE、`data.win`、必要配置与自写资源摘要。准备器拒绝未知成品、路径链接、被修改资源及不匹配组件；不能在每次准备时把任意新摘要自动加入白名单。
- 使用本地完整自写构建作为单独组件输入；用户运行受管入口时不要求安装 IDE／编译器。主程序发布包只含自有插件和源码，不自动捆绑官方工具、运行库或商业资产。未来若分发自写编译成品，先单独核对其许可与发布范围。

## 控制链与目标协议

1. 准备器新建专用运行目录，复制登记组件，并通过已有受管会话创建独立桌面和 Job。挂起创建目标后先写会话绑定，再调用 `run()`。会话配置绑定随机会话 ID、目标 PID 与协议版本；目标不接受任意绝对路径或代码。
2. Python 宿主沿用统一客户端请求、动作 ID、租约及结果格式。宿主到目标采用有界定长记录，逐代只发布一次，避免反复替换目标当前打开的命令文件。记录包含版本、会话、PID、唯一序号、动作种类和期限；未知枚举、字段溢出、重复／倒退序号、短读及身份不符均拒绝。
3. 目标每次 Step 输入查询前核对命令与期限，设置当前进程中右键的合成状态；同一 Step 原场景继续通过正常 `keyboard_check` 决定是否移动。只公开 `right`；不覆盖用户桌面、不发送系统输入，不提供全局按键接口。
4. 自写事件在正常查询之后提交有身份的采样结果；桥发布状态时区分命令接受、按下实际采样和释放实际采样。宿主只在编号、会话和当前目标观察相符时确认，旧回执不能结束新动作。
5. 宿主取得新目标采样、相应消费／释放记录和生产截图后返回 MCP。新会话先暂停且不持键，取得有效首图后显式恢复。暂停只停止合成输入，不承诺暂停游戏仿真。

字段布局见 `plugins/gamemaker/BridgeState.h` 与 `channel.py`：48 字节绑定、72 字节命令和 80 字节消费记录，严格解析测试在 `tests/test_gamemaker_bridge.py`。实验的 16 字节 `input.bin` 未延用。

## 计时、失败与生命周期

沿用协议 2 的单动作 1–1,000 ms、租约 1.5 s、停帧／释放 1 s、截图 3 s、启动 15 s，以及现有黑白帧门槛。Step 次数和 Present 次数不换算毫秒，不宣称为完整游戏逻辑帧。

- 目标使用原语实验已调用的 `GetTickCount64` 检查单次动作与租约绝对期限；宿主须用同一 Windows 单调时基构造目标期限。字段范围检查独立于到期比较，拒绝超出上限的期限，不因心跳续租延长当前动作。
- 正式持键开放前，另验时钟在目标挂起／恢复后的行为及首个恢复采样拒绝旧命令；当前短时自然到期成功不能代替停帧恢复验证。
- 松键、暂停、无效当前记录、通道丢失或租约到期均清除合成状态；目标发布可区别的原因。宿主无法确认释放时如实保留“已消费／释放未知”，并回收自有 Job，不把进程退出描述为正常松键消费。
- 目标停帧时无法执行 Step，宿主按既有活性期限终止；恢复时不得重放过期动作。宿主／MCP 被结束后，目标期限与 Job 回收仍分别验证。
- 目标读取／发布失败导致活性丢失时安全停手；不为文件竞争扩大期限。文件 I/O 不作为实时调度保证，受管宿主需保留超时和回收边界。
- 截图失败后不发后续游戏动作；有效首图前保持暂停。不得使用置前台或用户桌面输入作为回退，也不调低图像守卫。

## 写入、来源与还原

源商业游戏、存档和原用户配置只读。测试只用自写场景；场景不调用保存 API，所有会话文件、临时输出与证据位于任务目录。固定运行组件可能存在自身平台行为，需再核对已知 AppData／注册表路径；独立桌面与复制目录不等于文件系统沙箱，不承诺零 C 盘写入。

保留构建前源码清单、组件来源／许可、每个副本的生成文件和回收清单。自写源码与官方组件分开记录，不转载商业资源。回退时停止会话、回收自有进程、撤销插件／登记并停止使用该组件，无原游戏存档迁移。

原商业候选及归档按已有条件式删除授权，在相关验证收口后列明完整路径与实际占用再删除；本设计及自写实验完成不自动视为商业验证收口。

## 实施与验收

1. 先写会因行为缺失失败的严格解析、固定组件拒绝、身份／序号、暂停／期限、消费／释放测试，再实现最小目标状态机。未知哈希、短读、损坏数据、超上限期限、重复请求和迟到状态不得启动输入。
2. 构建登记自写目标，重验有效首图、后台持续新画面、普通查询消费、两张持键图与两张释放后图；正常输入逻辑和桥状态互相印证。补目标停帧／恢复与计时实测后，才开放正式有限持键。
3. 通过真实统一 MCP 验证暂停启动、恢复、右移、等待、人工暂停和关闭；覆盖租约到期、通道失败、目标停帧、截图故障、双会话隔离、创建者正常退出及强制结束。
4. 接同一冻结 worker，运行受影响测试及便携版关键真实 MCP 用例；确认资产无官方开发工具、运行库或商业内容。补组件要求、来源、升级／回退、覆盖表和变更记录。
5. 全部适用验收通过后，只将覆盖表更新为“固定自写 YYC 构建受管右移／等待”。商业程序、VM 输入、其他构建、其他按键、鼠标、菜单、存读档、音频、真人并发和长期稳定性均单独保留未验。
