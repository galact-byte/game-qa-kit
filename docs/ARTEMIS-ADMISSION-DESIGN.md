# Artemis 自写场景脚本桥接入设计

日期：2026-11-19。状态：设计已批准并完成首版实现。固定运行时＋登记自写场景的源码／便携受管 MCP 正常路径和故障生命周期已验；范围只含右移与等待。`clock-probe-01`～`03` 的无效首图是历史失败，后续新增窗口／桌面／取图边界证据通过门槛后继续实施。偶发无效首图根因仍未定位，不降低判据或追认旧批次成功。

## 目标与依据

让统一 MCP 动作层通过 Artemis 自身的 Lua 输入覆盖表控制登记的自写场景，在独立桌面后台运行、持续取图，按住期间经过普通输入查询驱动场景，松开后停止。原商业游戏目录保持只读。首版只验证右移与等待；商业场景、其他版本、鼠标、菜单、存读档、音频与长期稳定性不在本设计交付范围内。

固定目标是本机提供的 x64 `HaitokunoShoudou.exe`，SHA-256 为 `4480a20da5857ea329036c3031e671241f5efb73e9f75bf07412834d3c0a60b2`。不将该商业运行程序、附带 DLL 或商业资源加入源码库、主发布包或测试资产。

[预检记录](ARTEMIS-PREFLIGHT.md)及本地 `<Artemis预检目录>/preflight-01/input-static-01/` 保存静态证据。REA 的 IDA 后端实际反编译与调用链核对表明，`overrideKey` 接收 `key`／`status` 并写入正常按键查询读取的覆盖表。自写实测进一步确认：

- `input-probe-01`：单次覆盖只短暂影响采样，色块 x=80→82 后停住，持续按住断言失败。失败原样保留。
- `input-probe-02`：每次采样前重申覆盖，按住截图 x=84→104，松开后两张均 x=110。
- `input-probe-03`：按住／松键状态由 `onEnterFrame` 回调重申，普通场景循环独立调用 `isDown(39)`；按住截图 x=86→106，松开后两张均 x=110。该探针的 `clear` 清理仍由普通场景循环执行，未证明正式桥的故障释放机制。

两批成功探针均先取得有效首图再输入，每帧标记 2,501 像素；自写场景只在正常输入查询为真时移动。它们证明输入原语与逐帧重申可用，不等于已通过 MCP、租约或商业验收。

## 方案选择

已实现 `plugins/artemis/` 的 Lua 脚本桥与 Python 宿主，复用现有 `gameqakit/control.py` 的协议 2、`duration_host.py`、`duration_session.py` 和生产截图通路。首版用 `duration_ms`；回调次数仅作活性／诊断字段，不能按固定频率换算毫秒，也不能宣称是真实仿真帧。

脚本接口已得到实际输入与画面证据，因此本设计不引入 DLL 注入、原生钩子或原生加载器。若后续证据要求改为这些方式，应另列设计及批准边界。直接调用游戏按钮回调、移动场景状态、切换场景或定时移动色块不能代替控制链。

## 组件与数据流

1. 准备器仅接受登记哈希的本地运行程序及必要运行 DLL，生成独立自写工程、Lua 桥、会话配置与专用 `savedata`／临时目录。校验源文件，拒绝未知版本、被修改的场景或配置，不修改或启动原商业目录。
2. 宿主在现有 Win32 Desktop＋Job Object 内启动副本。它复用统一客户端文件协议的会话身份、命令 ID、租约与结果格式；宿主与 Lua 之间使用固定字段、严格解析的小型命令／状态文件，不执行传入代码或任意路径。实测同名文件原子替换会与目标 CRT 打开冲突，实施后改为逐代只发布一次。尚未读入的新代次暂时不可打开时保留当前记录及原期限；当前命令缺失、短读或无效立即撤销输入，不替其续命。
3. 自写启动脚本安装 `onEnterFrame` 处理器；该首版自写工程拥有回调，不覆盖商业处理器，也不宣称解决未知处理器的链式挂接。处理器读取有界命令、核对身份和时效，再重申右键覆盖；普通场景循环通过 `isDown` 查询并执行原本的移动逻辑。
4. 只有普通场景逻辑实际采样后，目标才发布相应命令的消费记录。覆盖写入成功、回调次数递增或宿主发送成功不能单独构成消费确认。按下与松开分别有命令身份，禁止复用旧故障命令或旧会话的释放回执。
5. 宿主取得新目标观察、消费／释放回执和生产截图后，经既有统一 MCP 结果返回。新会话先暂停且不持键，取得有效首图后再显式恢复；暂停只关闭合成输入，不承诺暂停游戏仿真。

## 生命周期与失败处理

- 单动作上限沿用现有协议的 1,000 ms；租约 1.5 s、停帧 1 s、截图 3 s、启动 15 s，沿用现有规则，不因 Artemis 降低黑白帧阈值或扩大期限。
- 目标端使用已核对的 `now` 毫秒值，静态链路读取 `timeGetTime` 并清除最高位；期限按模 2³¹ 比较。`clock-probe-04` 挂起 1.703 秒期间不能发布新采样，恢复首条读数前进 1.779 秒，包含停顿时间。不能把未发布新采样描述为时钟停止。输入期限检查在逐帧和普通采样入口执行，不用回调计数或 CPU 时间换算时长。
- 实施前先通过新增取图边界、目标端计时和到期撤销探针，随后才开放有限持键。真实引擎 Lua 用例另验回绕、过期、短读和采样后消费，未引入新原生组件或放宽期限。
- 暂停、松键、租约失效、命令无效、通道丢失或脚本错误均撤销合成持键并发布可区分的回执。目标停帧或退出导致无法确认释放时，宿主如实返回已观察到的消费与释放未知，终止自有 Job；不能把进程退出写成游戏已消费松键。
- 宿主／MCP 中断、目标停帧、截图失败分别验证。独立桌面不隔离文件系统、注册表、网络或任意 AppData；准备器只配置并核对已知写入路径，不作全面沙箱承诺。
- 不置前台、不移动实体光标、不向用户桌面发送输入。前台采样记录窗口和进程身份，仅拒绝本批游戏／工作进程占用用户前台，允许用户正常切换其他应用。

## 变更与还原边界

已新增 `plugins/artemis/`，修改识别、受管登记与 worker 分派，补测试及文档。复用既有协议与宿主，不增加全局输入后门、网络服务或依赖下载。首版按钮能力只公布 `right`；不把尚未验证的其他方向、确认键或鼠标列为可用。

源游戏全部只读，启动前后校验原 1,127 个文件；额外生成的场景、命令、状态、截图和 `savedata` 均位于任务专用副本。保存测试变更清单与还原方法，保留原进度与失败证据。回退时停会话、回收自有进程、回退代码登记并停止使用该副本即可，无原游戏存档迁移。删除含保存数据或证据的副本仍遵守既有删除批准边界。

分发仅包含自有桥、源代码、说明与自绘场景；本地运行程序及 DLL 的来源、版本、摘要和所需权利在准备器说明及来源清单中记录。任何复制第三方桥代码或引入组件时先补来源与许可证。本设计不批准转载商业运行程序。

## 实施与验收顺序

1. 先为登记拒绝、严格命令解析、命令代次、租约／暂停状态、计时失效与消费确认编写可失败测试，再做最小实现。自写场景实测计时接口、输入覆盖清零／释放语义和回调时序；失败时保留证据，不外推商业兼容。
2. 源码版通过真实统一 MCP：暂停启动、有效首图、恢复、右移、等待、松键停住、人工暂停及关闭。用两张持键截图和两张释放后截图，结合普通场景消费记录核对，不只检查宿主结果布尔值。
3. 覆盖会话串用、重复／过期命令、未知哈希、篡改场景、通道短读、宿主退出、租约过期、目标停帧、截图失败和双会话隔离；保留已消费但释放未确认的事实。所有失败均回收自有进程，不扩大写入范围。
4. 接冻结 worker 与便携包，运行受影响回归及同一组真实 MCP 关键用例，核对打包资产不含商业二进制。补接入说明、来源清单、覆盖表与变更记录。
5. 只有全部适用验收通过后，才能将覆盖表改为“固定运行时＋登记自写场景受管通路”。商业入口仍未验，需独立范围与完整副本批准。
