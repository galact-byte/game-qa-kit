# Artemis 自写场景后台预检

本记录对应固定 Windows 构建的进入条件验证，不代表 Artemis 已适配。

## 已确认的条件

- 本地候选为《背徳の衝動》ver1.10 的目录，存在运行程序、脚本、资源包和保存配置。只读核对不等于已验证商业游戏完整可玩，本批没有启动商业入口。
- `HaitokunoShoudou.exe` 的 SHA-256 为 `4480a20da5857ea329036c3031e671241f5efb73e9f75bf07412834d3c0a60b2`。
- 原 `system.ini` 在 `[WINDOWS]` 节使用 `BOOT=system/main.iet`，以相对路径 `savedata` 配置保存目录，并提供 `FORCE_SOFTWARE_RENDER` 开关。原脚本存在 IEScript 图层、过渡、位置与 Lua 标签。
- 独立副本只复制运行程序与 `d3dcompiler_47.dll`，另写配置、脚本与自绘图片。副本未携带商业脚本、图像或 `root.pfs`。运行窗口实际出现自写脚本指定的标题，证明该固定运行程序能够执行自写 BOOT 脚本。

## 零输入结果

通过现有 `DesktopProcess` 的独立桌面与 Job Object 启动；没有输入投递、二进制修改、插件注入、实体光标移动、软件下载或安装。

| 批次 | 本批区别 | 结果 |
| --- | --- | --- |
| `zero-input-01` | 自绘 PNG、精确匹配 640×480 客户区 | 实际窗口为 512×384，探针未匹配；没有取图和输入。该结果不能单独作为绘制失败证据 |
| `startup-diagnostic-01` | 只观察首批副本，记录真实窗口类、标题并取首图 | 类名 `Artemis`、自写标题成立；生产取图层判定 100% 黑帧并停止 |
| `zero-input-02` | 按窗口类与配置宽高比选择窗口；改用样本已有语法的纯色图层与位置 | 首图被判定为 100% 黑帧；取图早于自写标题出现，保留准备阶段歧义 |
| `zero-input-03` | 等待自写标题出现，仍受 15 秒启动期限限制 | 脚本已执行后的首图仍为 100% 黑帧，停止 |
| `zero-input-04` | 第三批基础上仅启用配置中已有的软件渲染开关 | 首图仍为 100% 黑帧，停止 |

生产取图层的 99.9% 黑白帧判据、三秒取图期限与十五秒启动期限均未放宽。无效截图按原规则拒绝落盘，记录中不存在可供可视验收的合格场景截图。

各批原目录前后 **1,127 个文件**的 SHA-256 一致；测试目标退出，最终任务目录下无运行程序残留。首批只在自写副本产生 `savedata/saveg.dat` 和 `savedata/system.dat`，未改动原存档。该核对不覆盖系统全盘、注册表或任意外部持久化位置，独立桌面不等同文件系统隔离。

## 当前阻碍与恢复条件

当前停在“BOOT 脚本执行，但独立桌面首图无效”。绘制消息、实际渲染、图层建立与取图路径尚未明确区分，不能归因为资源包缺失、失焦暂停或引擎不支持后台运行。尚未验证持续新画面、不抢键鼠的输入通路、消费与松键、暂停、受管接入或商业玩法。

同一问题的三次修正后仍未取得有效首图，按停止条件保留现场，不继续猜接口试跑。恢复时先取得能够定位目标绘制或取图边界的具体新证据，仍从自写副本开始；不得转为置前台、真实光标或 `SendInput` 绕过后台要求。涉及原生加载器、注入、商业场景改造、新软件下载或系统级诊断时，另列范围与还原方式并按对应批准边界执行。

本机没有可用的深度二进制分析后端，只记录二进制元数据和待查字符串线索；字符串不构成接口证据。
