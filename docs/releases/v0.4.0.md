# v0.4.0 — 七类自写样本受管接入、Flash 后台控制与 Godot 稳定性修复

这是 v0.3.1 之后的一次功能更新。本次把 Godot、Ren'Py、TyranoScript、Emuera、KiriKiri、HSP 和 Flash 的**固定自写样本**接入统一的「AI 后台接入」流程：检查组件、准备副本、取得暂停首图，再交给 MCP 操作，并在故障时保留回执和回收进程。

对于已经使用实验插件的用户，这次的主要变化是可以从统一入口准备和启动下列样本，便携版也包含对应接入模块、桥脚本和已入库的样本文件。**这不代表这些引擎的任意商业游戏已经可以接入**；版本、组件摘要和已验范围仍会逐项检查。

## ✨ 新增功能

### 七类自写样本进入统一后台接入流程

此前，下列引擎主要通过独立实验入口验证，或在通用入口中只做识别。本次将通过验收的固定自写样本接到 GUI 和 MCP 共用的准备、启动与停止流程，减少手动拼接启动器、桥和会话的步骤。

| 引擎与已验版本 | 本次新增的受管能力 | 范围与准备条件 |
| --- | --- | --- |
| **Godot 4.5.1** | 暂停首图、方向键移动、场景读取松键、黑屏后停止输入与进程回收 | 仅登记的自写 PCK 和固定运行时；运行时需另行提供 |
| **Ren'Py 8.3.2** | 从通用入口启动自写场景，真实 MCP 验证移动、松键与无效画面后的回收 | 仅登记的场景和运行组件完整清单；不启动原商业工程 |
| **TyranoScript Ver5（500）／Electron 7.1.2** | Enter 确认推进、松键和无输入等待，黑屏后保留消费回执并停止会话 | 仅固定组件和自写场景；鼠标及其他版本未验 |
| **Emuera 1.824** | 等待场景进入首次 WAIT 后取得首图，再通过确认和等待推进 | 需匹配的运行时及本机 .NET Framework 4 C# 编译器；不随包提供原运行时 |
| **KiriKiri 2.32.2.426 x86** | 自写 Window 样本的暂停预览、Enter 确认、松键和等待 | 需匹配的运行时；本次通用入口不开放商业 KAG |
| **HSP 3.7 x86** | 自写样本的持续预览、角色右移、菜单开关、松键与退出 | 需匹配的 `hsp3.exe` 和已构建的 `GameQaHsp.dll`；商业字节码仍走独立入口 |
| **Flash AVM1** | 通过 Ruffle Web 运行自写 SWF，持续取图、右键移动、松键与故障回收 | 需登记的 Edge 157.0.4341.60；Ruffle Web 0.7.1 自托管资源随包提供 |

以上版本号只用于说明兼容范围，实际准备和启动还会验证文件 SHA-256；同版本的不同构建不会直接视为兼容。缺组件或摘要不匹配时，界面会说明原因，不会自动下载运行时或修改原游戏。

### Flash 首次提供受管的浏览器运行通路

新增 Flash 入口使用随包的官方 Ruffle Web 自托管资源和本机已安装的固定 Edge 构建。它不依赖用户浏览器中的 Ruffle 扩展，也不要求安装 Adobe Flash 插件。

- 使用独立浏览器配置、独立 Windows 桌面和私有 CDP 管道，不开放调试端口，不复用日常浏览器配置。
- 自写 SWF 的真实 MCP 画面验证：按住右方向键时色块从 `x=40` 移到 `x=128`，松开后回到原位。
- 首图不合格时不发送输入；渲染器卡死或浏览器退出时，由宿主回收本会话的进程树。
- 故障回执区分“按下已观察到”“松开已确认”和“进程已退出”。卡死、退出用例只确认了按下及进程回收，不会把无法观察到的松开记成成功。

Adobe 独立播放器与 Ruffle Desktop 的后台取图预检未得到有效首图，本次不将它们作为可用入口。商业 SWF、投影器、鼠标、存读档及其他浏览器构建仍未验。

## 🛠️ 修复与优化

### 修复 Godot 续租文件短暂读取失败导致的会话中断

Windows 原子更新租约文件时，桥偶尔会遇到文件暂时无法打开，导致原本仍有效的会话被判定为租约失效。现在仅对这一类短暂打开失败进行有限重试，再重新校验文件内容，减少该路径引起的错误中断。

该修复不复用旧租约，也不放宽失效期限；真实的租约失效仍会停止输入。已验证的瞬时打开失败与更早一次未确认根因的 `lease_expired` 记录分别保留，未将所有租约异常归为同一原因。

### 修复便携版新增入口的启动与取图路径

- 为冻结后的独立取图 worker 补齐模块入口，使 Emuera／KiriKiri 等新接入流程可以从打包后的 EXE 启动取图子进程。
- Flash 复用 Edge 启动时的初始标签页，避免便携版在首图前等待额外标签页而超时。
- Flash 改为在确认 SWF 已播放、页面导航完成后再聚焦播放器，修复过早聚焦被导航重置、右方向键未进入样本的问题。
- 便携自检新增对接入模块、样本和 Flash 资源摘要的检查；Ruffle 的上游来源与许可证随包附带。

### 更新引擎盘点，区分“识别到”与“能够控制”

重新核对工具目录、运行时、游戏组件及重复 EXE，补充 EasyRPG、YU-RIS 和 AGE_System 的材料线索。盘点表与路线图已同步，但这些新线索没有增加产品控制能力；工具数量和候选目录数量也不再用作游戏覆盖数量。

## 🔄 兼容性与升级说明

- **平台仍为 Windows 64 位。**主程序便携包包含 GameQA 自身的 Python／Qt 运行环境，解压即可启动；各引擎的额外运行时、原生桥和编译工具不因此变成随包提供，需按接入检查结果准备。
- **新增入口仍为实验支持。**新增七类入口的结论只适用于登记的自写样本和固定组件，商业内容、其他构建、长期运行及真人同时操作键鼠需分别验收。
- **Flash 对 Edge 构建有明确限制。**只有登记的 Edge 157.0.4341.60 及匹配文件摘要通过本轮验收。Edge 自动更新后可能被拒绝接入，不能仅凭版本相近继续使用。
- **KiriKiri 商业控制与音频问题没有在本版解决。**本次增加的是自写 Window 的通用入口；此前商业 KAG 和 DirectSound 失败记录仍有效。
- **DuckStation 通用入口仍未收口。**需要登记构建、配套组件、合法 BIOS 及已授权的镜像与轨道文件，不列为本次新增可用入口。
- **原游戏数据无需迁移。**建议解压到新目录，结束旧会话后再切换 MCP 的 EXE 路径；需要保留配置时复制原 `profiles/` 和相应 `data/`，不要覆盖正在使用的目录。已准备的实验样本建议用本版重新创建副本，避免混用新旧桥和宿主。
- **输入暂停仍只是暂停工具输入。**独立 Windows 桌面隔离桌面输入，不等同于文件系统、注册表或网络沙箱，也不表示游戏仿真已经暂停。

## 📦 下载与开始使用

| 发布资产 | 用途 |
| --- | --- |
| `game-qa-kit-v0.4.0-windows-x64.zip` | 主便携包，内含 `GameQA.exe`、`GameQA-MCP.exe`、运行依赖、接入模块、已入库自写样本及第三方许可材料 |
| `SHA256SUMS.txt` | 主便携 ZIP 的 SHA-256 校验清单 |

1. 将主便携包解压到一个新的可写目录，运行 `GameQA/GameQA.exe`。
2. 在主界面打开「AI 后台接入」，选择已验样本目录、新的 QA 数据目录和对应组件目录。便携包中的样本位于 `GameQA/_internal/plugins/<引擎>/samples/`，具体布局按插件说明准备。
3. 检查组件与即将创建的副本，确认准备和启动。取得有效首图后，输入仍保持暂停，可以先查看预览。
4. 在 AI 客户端配置 `GameQA/GameQA-MCP.exe`，绑定会话并显式恢复输入后操作；结束时调用 `game_stop`，保留截图和结束回执供复核。

构建流程会先运行便携入口、游戏接入、会话生命周期、MCP 与 GUI 的定向回归，再执行便携版模块导入、冻结子进程、MCP 工具列表和 Qt 窗口自检。真实引擎测试需要本机组件，不能将缺少组件而未运行的项目视为已验；各引擎的开发阶段实测和未验范围见下方文档。
