## Artemis 自写场景可以从统一入口启动

本版将 Artemis 的自写场景接入「AI 后台接入」，可以从界面或 MCP 检查组件、准备测试副本、启动和停止会话。目前可以让场景中的色块向右移动，也可以等待一段时间并查看画面。

启动后先显示画面，自动输入保持暂停。确认画面正常、绑定会话并恢复输入后，才能操作样本。暂停只停止自动输入，游戏本身仍会继续运行。

插件和自写样本已随包附带，运行需要另外准备已登记的 x64 EXE 和 `d3dcompiler_47.dll`。工具会核对文件摘要，只复制这两个组件和自写场景，不复制商业剧情或原存档。原游戏运行组件不在主 ZIP 中；其他版本、构建或修改过的样本不能直接替代，缺少组件或文件不匹配时会提示原因。

移动和松键的结果由目标场景正常读取按键后确认。两个后台会话可以分别操作和关闭；取图失败、请求过期或目标停止响应时，会停止后续输入并按实际情况回收会话进程。无法确认松键时，结束记录会保留这一结果。

## 当前限制

Artemis 的支持限于登记自写场景的右移和等待。商业游戏启动与玩法、其他构建、其他方向、鼠标、菜单、存读档、音频、长期运行和真人同时操作键鼠尚未验证。

验证过程中曾出现首张画面无效，原因尚未查明。遇到这一情况，工具会停止启动，不发送操作；后续成功批次不代表这个问题已经修复。

Windows 检出源码时，固定样本的两个文件会保持 LF 换行，避免自动换行转换导致摘要不匹配、无法准备样本。

其他引擎的组件要求与支持范围沿用 v0.4.1。YU-RIS 暂缓适配，等待完整且允许测试的新样本，本版没有新增对应控制入口。

## 下载和升级

下载 `game-qa-kit-v0.4.2-windows-x64.zip`，完整解压到新目录后运行 `GameQA/GameQA.exe`。MCP 客户端使用同目录的 `GameQA-MCP.exe`。支持 Windows x64，主程序不需要另外安装 Python；校验文件为 `SHA256SUMS.txt`。

升级前结束旧会话，再迁移自己的 `profiles/` 和 `data/`，并更新 MCP 的程序路径。保留新包的 `_internal` 文件夹，测试样本请重新准备副本，避免混用新旧桥和会话文件。

Artemis 样本位于 `GameQA/_internal/plugins/artemis/samples/authored/`。在「AI 后台接入」选择这个目录、匹配的运行组件和新的 QA 数据目录，即可准备测试副本。
