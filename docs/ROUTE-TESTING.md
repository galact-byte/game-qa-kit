# 从测试检查点执行一段路线

这条流程适合这样的任务：让 AI 从准备好的测试进度出发，走到指定地点、打开菜单或检查一段对话，最后给出每步画面、停止位置和复核结论。它不是自动通关，也不是自动发现所有问题。

本功能尚未正式发布。请先确认所用源码或本地预览包的 MCP 工具列表包含 `route_begin`、`route_step`、`route_status`、`route_finish`；旧版便携包不会自动获得这些工具。

## 使用步骤

1. 在「AI 后台接入」选择已支持的游戏、组件和 QA 数据目录。如需从测试进度开始，选择独立的「测试检查点」，只读检查后确认并启动。检查点目前只开放给已登记的 VX Ace 构建，条件见[游戏接入说明](GAME-ADMISSION.md#从专用测试检查点准备实验)。
2. 在已连接 GameQA MCP 的 AI 客户端说明任务和终点，例如：

   > 连接我刚创建的测试副本。从导入的 1 号测试档开始，走到大客厅，打开菜单，再返回起点。请记录具名步骤，每次操作后看新截图；遇到错误或结果未知就停止，不重复发送动作。结束后先关闭测试副本并确认回收，再给出结果页。不要操作我的正常游戏窗口，也不要保存或改写原档。

3. AI 需要明确绑定该会话并使用路线工具。只是给它发一段自然语言，不代表工具已经自动安排路线；如果它尚未连接 MCP 或游戏不支持后台操作，应先说明缺项。
4. 在「AI 后台接入」点「查看测试结果」。会话结束后，也可选择原 QA 数据目录，点「查找会话」、选择该记录，再打开结果；无需重启游戏或重新取得动作权。

只想自己玩、让工具记画面时，继续使用主界面的人工盯屏。路线模式不替代人工入口，也不向正常游戏窗口发送前台输入。

## 结果页怎么看

- **动作执行**：桥接动作是否有本轮成功回执和匹配截图。全部动作完成，不代表走对路线或玩法目标已达成。
- **最后步骤和停止原因**：具体停在哪一步；失败、未知结果或未确认松键会阻断后续步骤。
- **AI 复核**：AI 检查画面后声明「目标达成」「目标未达成」或「尚未复核目标」。这不是工具自动识别的游戏结论，仍可按图复查。
- **实例回收**：单独显示是否确认关闭。结束记录不等于关闭游戏，缺少停止确认就不能写成已回收。
- **每步画面**：图片随报告保留在 `route-reports/<路线编号>/images/`，可点开原图。带走结果时复制整个路线编号文件夹，不要只复制 HTML。

检查点文件已导入，不等于游戏内已经读档。报告会保留导入信息，AI 仍需通过游戏自己的菜单加载并核对读档后的画面。

## 给 AI 客户端的调用约定

已有 `game_inspect`、`game_prepare`、`game_start` 和 `game_bind` 流程不变。目标、副本位置、组件和数据处置范围仍需先确认；不要把正常游戏目录当作会话目录。

| 工具 | 用法 |
| --- | --- |
| `route_begin` | `goal`、`confirm=true`；在已显式绑定且持有动作权的目标上开始记录，不自动读档、不自动规划 |
| `route_step` | `step_id`、`label`、`action`、既有控制参数、`confirm=true`；恢复输入、执行一个动作、保存对应画面，再确认暂停松键 |
| `route_status` | 查询当前记录、停止原因和 `report_html`，不发送输入 |
| `route_finish` | `outcome` 可为 `passed`、`failed`、`unverified`，默认未复核；前两者必须提供 `note`，并需 `confirm=true`。只结束记录，不代替 `game_stop` |

例如一个 VX Ace 观察步骤：

```json
{
  "step_id": "loaded-map",
  "label": "核对读档后的地图",
  "action": "wait",
  "frames": 1,
  "confirm": true
}
```

默认返回本步图片，允许 `include_image=false` 仅返回记录；正式作玩法判断时仍需读取对应画面。动作参数沿用当前桥的协议：帧制和毫秒制不能混用，不能凭通用示例推断引擎支持的动作。

相同 `step_id` 和内容重复调用只返回原结果；不能用同一编号提交不同动作。失败或超时后，不要另换编号重发：先查询原命令和记录。路线记录期间 `control_action`、`control_resume` 会拒绝未记录的旁路动作，状态查询和暂停仍可使用。

正常收尾顺序是：核对截图，解绑动作连接，通过创建者调用 `game_stop`，查询到停止与清理确认，再调用 `route_finish`。不是创建者时，应由原创建者完成停止；不能绕过所有权。连接正常结束时会沿用既有回收逻辑并尝试保留未复核报告；强制终止、断电或落盘失败不能保证最终报告完整，保留最后落盘状态，不能据此宣称目标通过或正常回收。

## 已验证的用法

Windows 源码已在登记的 RGSS300 备用副本完成一段完整任务：读入一号测试档，走到大客厅，打开并关闭菜单，再返回起点。33 步画面逐张核对，报告分别记载目标达成与实例回收；不支持动作被拒后，后续输入停止，创建者退出后测试实例回收也已验证。

本轮同时修正了动作与持续观察截图串联导致心跳过期的调度缺陷，未延长两秒心跳或五秒动作期限。旧失败记录保留；这一段短路线通过不表示任意游戏、其他构建或长期运行均已验证。旧 v0.4.7 候选没有包含这些改动，尚未制作包含本功能的新便携包。

## 当前限制

- 依赖现有 AI 客户端和已支持的控制桥；程序不内置模型、攻略或通用路线规划器。
- 记录器不扩展引擎、商业构建、存读档或并发支持范围，具体以[引擎覆盖表](ENGINE-COVERAGE.md)为准。
- 暂停松键不一定冻结游戏仿真，尤其不能把原生输入后端的输入暂停当作进程暂停。
- 首图失败、过期心跳或无法确认画面时停止，不通过抢前台、延长期限或重复发送未知动作兜底。
