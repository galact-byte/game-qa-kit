# Bakin 固定商业构建受管入口设计

日期：2026-11-20。状态：设计已获用户明确批准，基础受管入口与后续共享内存通道已实现，固定商业构建已取得标题、加载审核／恢复及对白操作证据；完整玩法与故障生命周期仍未验收，当前不追加实机批次。批准包括本后端 60 秒播放器启动和独立 300 秒准备期限；3 秒截图、0.999 黑白帧判据及其余控制期限不变。正文保留原设计要求，后续实现、试验失败与未验范围以[插件说明](../plugins/bakin/README.md)和[支持表](ENGINE-COVERAGE.md)为准。

## 目标与证据边界

让统一 MCP 从一个干净的、合法持有的固定 Bakin 2.5.1.0 商业导出包创建独立运行副本，后台取图并通过普通输入查询完成标题菜单、新游戏、开场对白及后续可达的自由移动。补齐持键、松键、租约、暂停、异常退出与回收，不依赖旧实验脚本或已经删除的解包目录。

[预检记录](BAKIN-PREFLIGHT.md)仅证明临时补丁可持续取得 1280×720 画面，正常输入完成菜单下／上、新游戏和开场对白。最终批次 4 次输入各消费一个 tick 并归零；7 张图发布耗时 265–547 ms；播放器启动至首截图请求 29,078 ms。原游戏 104 文件（含 5 个存档）摘要一致。没有正式目标身份、严格指令通道、完整查询消费或故障生命周期验收。

本设计不扩大已验范围。下述加载流程、输入映射、期限与故障处理是原设计要求，不统一标为待实现；基础入口、加载生命周期及后续共享内存迁移已有实现与分批证据，最终整批仍未通过，四方向自由移动与实机父进程强杀回收尚未验收。自写 Bakin 工程仍缺失；自写协议及 CLR 夹具仅验证对应状态机，不能代替商业游戏通过。

## 方案选择

推荐采用**固定构建副本中的最小托管补丁，加现有协议 2 和受管生命周期**。在复制、校验后使用已有 Mono.Cecil 工具能力修改固定入口，不重编译原引擎，不做全局键鼠模拟、内存特征扫描或未知构建自动兼容。

| 路线 | 依据与代价 | 决定 |
| --- | --- | --- |
| 固定入口托管补丁 | 已有副本补丁、输入与同步渲染取图证据；需重做正式身份、输入语义和冷准备流程 | 采用 |
| 原生注入宿主／通用模组加载器 | 当前没有该 Bakin 构建的加载与生命周期证据，会增加新的原生挂钩和交付依赖 | 本版不引入 |
| 编辑器官方插件 | 当前没有可用自写导出工程；不能据此承诺商业导出包能动态加载插件 | 保留后续自写样本路线，不作为本版前置安装任务 |

选择协议 2 是因为 `GameMain.updateCore` 和 `GameMain.UpdateInput` 都可能调用 `Input.Update`，渲染又有独立计数；当前不能把某一回调次数称为完整游戏逻辑帧。动作使用 `duration_ms`，观察使用 `observation_seq`；不换算 `frames`，暂停只停止合成输入。

## 干净副本的两阶段启动

当前预检已删除 `runtime-copy` 与 `temp`。直接复用旧 `/TMP` 参数指向该目录不可复跑；在播放器上先打补丁再正常启动，也会被启动器从 `bakinplayer.pak` 覆盖。本版用以下两阶段方案解决，不依赖覆盖时机竞争：

1. 在新任务目录建立唯一完整副本，所有临时／解包／配置输出指向会话目录。源目录只读，不复制原 `savedata`。为复制、工具运行及准备阶段建立可取消的期限和回收记录。
2. 仅在副本启动器的固定 `Form1.doExecuteEngine` 中，将最后启动播放器的 `Process.Start(string, string)` 调用替换为自有“记录准备结果”桥。保留它之前的原生解包、播放器恢复和版本读取流程；桥记录原目标路径、原参数与本次 `tmpPath` 后返回相同签名所需的占位返回值。不得启动播放器；必须验证原调用返回值确实未被后续逻辑使用。这里是拟实现方案，尚未跑通。
3. 准备型启动器在自有独立桌面／Job 内运行。输出只能写绑定的任务目录；原参数以数据形式传递，不经 shell 执行。宿主验证准备回执身份、全部路径位于会话目录、解包组件摘要及完整性，并确认没有播放器被提前拉起。正常退出后回收准备 Job。超时、意外播放器或未登记组件均失败，不能继续第二阶段。
4. 启动器退出后才在副本 `bakinengine.dll` 的固定入口安装输入查询、取图和配置重定向补丁，加入自有桥组件；播放器保持原始字节，不再加入诊断启动日志。补丁输出写新文件、校验后替换，记录原摘要、补丁版本与输出摘要，禁止二次叠加补丁。
5. 复用 `DesktopProcess` 挂起创建真实播放器，在恢复线程前写入随机会话标识、PID、进程创建身份、桥版本和控制目录绑定，再 `run()`。工作目录为副本 `data`，沿用启动器实际产生的 `/TMP=数据目录|启动器路径|解包目录|数据版本` 参数与同一副本路径，不添加跳标题、切场景、载档或调试参数。
6. 保留被引用的副本启动器和解包目录直到播放器停止；不在运行中再调用启动器，以免覆盖补丁。初始状态为输入暂停、不持键；等待桥、正常输入／绘制活性、真实非最小化游戏窗口和有效首图后才返回 `ready_paused`。初始化 OpenGL 隐藏窗口及错误对话框不计作游戏窗口。

两阶段冷准备是首个真实验收门槛。若不能只记录原启动结果而完整保留必要初始化，停在准备失败，不改为重放旧临时目录，也不自行改造未知解包／认证路径。

## 输入映射与普通查询消费

### 为什么不能直接保留探针的输入方式

固定构建的 `InputCore.ChangeKeyStates` 将传入位集同时赋给 `nowState`、`triggerState`、`triggerState2`、`repeatState`。因此 `ForceSetState` 适合本轮单 tick 原语验证，却没有区分持续按住、刚按下、刚松开和重复。每个 tick 重复调用可能把长按变成连续触发。`Input.GetAxis` 另走设备绑定，并不直接读取这四个位集。

### 正式桥的约定

- 在固定 `Input.Update` 边界采样一个经过身份／序号／期限校验的合成输入快照。该序号只表示输入采样代次。单代内同一种状态的多次查询必须一致，不因查询次数多而重复产生按下边沿。
- 对固定的 `Input.GetState`、`Input.GetAxis` 入口增加合成输入查询分派。桥只控制正常输入查询的返回，不调用移动、剧情、场景或任务结果 API。隔离自动会话中支持的键使用合成状态，未按下／暂停／失效时返回中性值，不混入用户桌面键鼠或全局手柄状态；人工采集模式不安装此自动控制补丁。
- `DIRECT` 为当前持键集合，`TRIGGER` 为本次新按下集合，`TRIGGER_UP` 为本次新释放集合；`REPEAT` 单独计算，不能复用同一位集。确认／取消的按下边沿只发生一次。重复节奏及按键轴映射依据登记构建的绑定与调用约定确定并做真实复核，不能凭角色移动效果反推任意数值。
- 方向键在按键和轴两条普通查询路径保持一致。方向、确认、取消按固定枚举映射；未支持键、组合键、鼠标、触摸或参数拒绝，不转为操作系统输入。尚未通过真实验证的按钮／动作不对外宣告能力。
- 查询观察只记录游戏原逻辑实际调用时的动作编号、查询类型、采样代次、返回值和单调时间。桥自身为检查状态调用 getter，不得计为普通游戏消费。调用点不允许为取回执而人工补一次游戏查询。
- 按下已被正常查询、同动作释放后的中性状态已被正常查询，才分别给出消费与松键证据。仅接受命令、设置合成状态或某 tick 后清零都不等同于消费。没有释放查询即如实记录“释放未确认”，不能伪造回执；超期回收自有进程。
- 暂停、租约失效和错误立即撤销合成输入许可，取消尚未消费的动作；恢复需要新许可和新动作，不重放旧编号。保留现有人工观察／标记入口，人工接管前停队列并确认释放，不自动切换桌面或抢占焦点。
- 在副本初始化时沿用已知的 `SuppressCursorControl` 边界，所有新增代码不得调用置前台、用户桌面 `SendInput` 或真实光标移动。

首版目标能力为四方向、确认、取消和等待，单动作最多一个键。自由移动／长按是验收项，不因标题菜单通过而宣称完成；无法通过正常查询和连续画面确认时，保留明确阻碍和实际能力，不静默换成直接写位置。

## 通道、计时与状态语义

外部复用 [控制分派](../gameqakit/control.py)及[毫秒协议校验](../gameqakit/control_time.py)。不新增平行 MCP 动作，也不提供任意程序集、方法名、脚本或绝对输出路径。

- `protocol=2`、`timing_mode=duration_ms`、`pause_scope=input`、`simulation_pause=false`；不发布 `frame`／`capture_frame`。观察、输入采样和渲染序号各自有名，互不换算。
- 沿用统一 `move`／`confirm`／`cancel`／`wait` 和显式恢复；`frames`、原始 press／release、click、额外字段均拒绝。按钮和能力依据已验配置登记，不扩大公共协议。
- 宿主与桥采用有界文件通道、单活动作、随机会话标识、目标 PID／创建身份、单调递增命令号及唯一动作 ID。Bakin 私有通道 `bridge_version=2` 的命令包含动作、1–1000 ms 时长、发布后固定 1 s 的首次消费截止与最晚结束边界；拒绝旧版本、旧持键字段、未知字段、非法枚举、布尔冒充整数、溢出、短读、损坏及身份不符。
- 请求、回执按不可变代次发布，消费者不把文件存在当作完整写入。文件打开允许必要的读／写／删除共享；临时文件只在同一目录原子发布。旧回执不能完成新动作，重复编号不能重新持键，状态倒退不能刷新活性。
- 目标用 `GetTickCount64` 检查动作与租约绝对期限；宿主使用同一 Windows 单调时基构造开始截止与最晚结束，不把 Python 的相对起点当作目标时钟。经单独批准，持键从游戏首次普通非零查询消费时起计原时长；采样不算消费，回执记录消费时间及固定持键截止。等待超时、暂停、失租和故障取消待开始输入。心跳、重复查询与同编号重发不能延长期限或复活输入；挂起后恢复的首次查询先检查期限，再决定是否输出按键。
- 文件读写、JSON、PNG 编码和摘要工作放在后台 I/O／发布线程；输入和绘制回调只读写有界快照。状态发布不得持有输入共用锁。通道损坏或发布失败通过原子故障标志撤销输入，不能因发布线程被阻塞而持续持键；队列满或期限到期为失败，不扩容无限缓存。

| 边界 | 设计值及适用范围 |
| --- | --- |
| 单动作 | 首次普通查询消费后保持 1–1,000 ms，沿用协议 2；首次消费最多等待固定 1 s，未消费不能报成功 |
| 租约 | 1.5 s；失效撤销许可，续租不延长旧动作 |
| 停采样／释放确认 | 1 s；无法确认时停止并回收，不能将进程退出称为已消费松键 |
| 单次截图 | 请求到完整 PNG 及摘要发布不超过 3 s |
| 黑白帧 | 保持现有 0.999 判据；首图无效不发输入，后续无效图停止后续动作 |
| 真实播放器启动 | **拟申请本固定构建独立使用 60 s**，含有效首图；其他后端仍维持原值。本批观察批准不自动成为正式默认配置 |
| 副本复制与准备 | 独立报告阶段，不混入播放器启动成功指标；拟采用可取消的 300 s 硬上限，每次步骤不重置整阶段时限 |
| 正常动作结果 | 保持现有 `control_time.validate_result` 的 5,000 ms 总窗口，不用更长结果冒充通过 |
| 商业真实验证批次 | 每批最多 300 s，单批结束即回收；不能通过重开会话规避明确停止条件 |

加载期不能伪造新截图、消费或松键。若确认新游戏后不能在现有动作窗口得到有效新观察，应明确记录长加载与协议不兼容，停止该链路验收；本设计不授权放宽公共 5 s 结果窗、3 s 截图或 1 s 释放确认。需要额外加载生命周期时，依据实测另写具体变更再决定。

## 取图与结果关联

沿用已验 `Graphics.getRenderCapture` 同步读图，在固定 `GameMain.draw` 返回后、有效渲染上下文内执行。`GameView.processRequest` 的异步请求和 `PrintWindow` 不作默认回退；也不置前台补截图。

1. 每次取图绑定会话、请求 ID、当前动作／观察身份和新的 `capture_seq`，最多一个在途请求。游戏回调取得自有像素缓冲后，编码与发布在后台完成；不得把下一帧覆盖后的指针交给编码线程。
2. 全部 PNG 字节写完并可解码、尺寸合法、摘要正确且守卫通过，再发布含相同身份的回执。返回路径限于当前证据目录。3 s 从宿主提出请求开始计算，包含等待绘制、读图、编码、完整发布与校验，不只量 API 耗时。
3. 活性来源是新的游戏采样／渲染记录；I/O 心跳或重复旧图不能充当目标活性。相同像素并不必然是停帧，需结合新的目标序号判断。
4. 动作结果必须关联该动作真实按下、松键的普通查询记录，以及释放后的新观察和有效图像；未取得全部证据即失败，不使用先前菜单图拼接成功。
5. 初始 `NONE` 阶段不具备可控场景就绪条件，不提前宣告 ready；一旦实际请求得到黑白无效帧，保留原失败并停批，不用延迟重试筛掉失败首图。

## 受管接入与组件职责

复用 [接入分派](../gameqakit/admission.py)、[运行时校验](../gameqakit/admission_runtime.py)、[worker 生命周期](../gameqakit/game_worker.py)、[DurationSession](../gameqakit/duration_session.py)、[Supervisor](../gameqakit/duration_host.py)及[独立桌面／Job](../gameqakit/desktop.py)。具体差异留在 Bakin 模块，不复制另一整套通用生命周期。

| 拟新增／修改位置 | 职责与边界 |
| --- | --- |
| `plugins/bakin/prepare.py`、构建登记 | 冻结组件、复制、两阶段准备、唯一补丁校验和变更账本 |
| `plugins/bakin/` 的自有 C# 准备记录桥／补丁工具／输入与截图桥 | 只处理固定入口、会话状态机、普通输入映射与渲染读图；不含反编译引擎实现 |
| `plugins/bakin/channel.py`、`host.py`、`session.py` | 严格通道、消费核验、引擎读图集成、Bakin 独立启动期限和正常停止 |
| `gameqakit/admission.py`、`admission_runtime.py`、`game_worker.py` | 固定 `bakin` 后端的准备／运行时复核／worker 分派；未知构建拒绝 |
| `gameqakit/duration_session.py`、`duration_host.py` | 仅在现有扩展点不足时增加启动期限或截图来源 hook，旧后端默认行为有回归保护；不把 Bakin 套入默认窗口截图 |

## 写入、来源、还原与空间

实施使用新的 `<bakin-managed-validation>` 任务目录，创建本地 `AGENTS.md` 和可直接阅读的 `变更与还原记录.md`，填写完整对象路径、用途、改前摘要、备份、具体补丁、写入、还原步骤及结果。旧 `<bakin-commercial-preflight>` 只读保留证据，不覆盖历史结论或重跑旧脚本。

- 原游戏、原配置和全部原存档只读；不复制原进度，不触及第 9 槽，不向原目录同步测试进度。本轮只做输入与生命周期，不执行存档菜单保存／读取实验；游戏正常新建的自动存档若出现，归入副本写入账本。
- `Config.Initialize` 保留预检已验的配置重定向意图；TEMP／TMP 仅对任务子进程设定，其他已知用户写入逐项核对。独立桌面／Job 只隔离输入和进程回收，不等于文件系统、注册表或网络沙箱，不承诺任意未知位置零写入。
- 只建一个完整运行副本，持有它的解包目录，不再为每次观察复制约 6 GiB 资源包。旧批次实测副本与解包合计 6,806,226,790 字节，只作为本次空间估算依据，真实新占用另记；空间不足先停准备，不写 C 盘或另找未批准下载。
- 正常结束先撤销输入、取消动作，尽力取得释放查询，再停止并回收自有 Job。失联时保留“未确认释放”与失败原因；父宿主强制结束后的 Job 回收必须实测。
- 结束核对原件、原存档和已知公共配置，保留代码、原件摘要、最小补丁备份、图像、失败日志及账本。仅回收本任务可重建副本／解包目录；删除前逐项列完整路径及实际字节数，删除后确认不存在，不删除旧失败证据或原游戏。
- 升级／回退时停止旧会话，桥、通道和补丁登记作为同一版本重新准备；不复用旧绑定，不做存档迁移。准备失败的半成品不得对外恢复为 ready；清理失败保留目录和明确状态。
- 自有代码适用仓库许可，商业程序和资源不随主包或源码提交。Mono.Cecil 等现有工具须记录实际版本／摘要／上游 revision 与原始许可，核验分发义务后再打包；未核定来源的二进制不进入发布。用户运行时不要求安装编译器、编辑器或新 .NET 运行时；现有引擎运行环境不足即给出明确不支持原因，不自动安装。

## 验收顺序与停止条件

1. **纯状态与结构测试先行**：自写 CLR 夹具覆盖四种键状态、轴映射、相同采样的重复查询、持键截止、租约到期、挂起恢复、序号回退／重复、身份错误、损坏／短读、I/O 阻塞及有界队列。补丁器对未知摘要、方法缺失／多匹配、短分支、异常处理区和二次补丁拒绝；原件摘要不变。先见预期失败，再最小实现，不以复制实现的断言充数。
2. **干净准备与首图**：从没有历史 temp 的完整副本跑两阶段流程，确认准备阶段没有提前启动播放器；验证取消、准备超时、回执路径越界与解包身份不符。正式播放器仅在绑定后恢复，在拟定 60 s 内取得暂停有效首图；此阶段输入为零。
3. **真实普通输入与画面**：通过同一 MCP 顺序完成标题下／上、确认新游戏、对白确认／取消，再在正常可达自由移动场景验证四方向。每个方向至少核对持键两张及释放后两张新图，结合普通查询记录；长按确认不得意外连跳对白。无法到达自由移动不能跳场景或直接载入未批准存档，保留该缺口。
4. **完整失败生命周期**：真实验证暂停／恢复、租约到期、通道损坏／缺失／写入阻塞、截图超时／黑图／不完整图、目标停采样／挂起恢复、双会话串线拒绝、创建者正常退出／强制结束及进程树回收。记录释放已确认与释放未知，不能互换。后台操作期间检查前台和真实光标不被助手改变；真人并发另有真实证据才列为通过。
5. **统一及冻结入口**：受影响识别／接入／控制／MCP 单元回归，通过源码与便携冻结 worker 的相同真实链路，核对资产不含商业资源、调试残留或未声明第三方组件。没有外部组件的条件测试明确统计跳过，不写成全实测通过。
6. **收口**：复核原件与存档前后摘要、公共配置、进程回收、证据完整性与文件清理清单；同步[支持范围](ENGINE-COVERAGE.md)、预检、使用说明和 `CHANGES.md`。只有经过上述真实验证的固定构建与能力才能改成已支持。

源码回归沿用 `python -X utf8 -B -m unittest discover -s tests -p 'test_*.py'`；真实测试必须提供登记组件与本地证据目录。单元测试数量、条件跳过数量、证据审计数量和真实游戏动作数量分开记录。文档阶段只做事实／链接／补丁空白检查，不宣称这些运行检查已经通过。

出现无效首图、截图超过 3 s、启动超过获批期限、未知组件／挂点、原件或公共保存位置变化、目标身份不透明、放宽安全控制需求时立即停止对应批次，保留证据并还原。相同问题连续三次修复仍不解决，停止盲试并提交具体阻碍。不得为过验收降低图像阈值、增加前台回退或扩大期限。
