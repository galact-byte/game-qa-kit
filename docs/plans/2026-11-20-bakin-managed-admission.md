1. 在现有隔离源码工作区实施，另建本地 `<bakin-managed-validation>` 证据目录及变更还原账本。记录批准范围，冻结原件完整摘要和复制白名单。
2. RED：自写 CLR 夹具验证查询一致性、四种键状态、轴、显式消费、持键截止、租约及故障中性状态；Python 夹具验证严格通道和路径／身份／未知构建拒绝。先运行并确认目标行为缺失导致失败。
3. GREEN：实现纯输入状态、自有后台通道和固定结构补丁器。保留原件，不把反编译引擎代码纳入仓库。所有回调禁止文件 I/O、JSON 与图像编码。
4. RED → GREEN：准备器从冻结清单建立唯一完整副本；只记录原启动器目标与参数，确认没有提前运行播放器，核验解包来源并冻结输出。测试取消、超时、越界和摘要不符。

6. 分批真实验证均在独立桌面／Job，每批最多 300 秒：首图零输入 → MCP 菜单、对白和正常可达移动 → 失败生命周期。守卫失败立即停批，不降低期限或图像判据。
7. 运行 `python -X utf8 -B -m unittest discover -s tests -p 'test_*.py'`，另记真实验证／条件跳过。核对源码与便携 worker、资产来源许可和原件／存档摘要；记录还原与空间清理。
8. 更新覆盖、使用文档、CHANGES 与本地交接。仅真实通过能力可启用。设计不含推送／发布。

验证证据分别记录单元测试、结构测试、真实动作、截图与消费、失败释放与进程回收，不以静态检查替代真实游戏。
