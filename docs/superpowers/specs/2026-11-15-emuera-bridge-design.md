# Emuera 固定构建实验桥接入设计

状态：2026-11-16 已按恢复工作时的继续指令实施固定构建自写工程实验桥；原入口、分发后输入消费、v2 协议、独立回收与正常存读档已验。实现见 [插件说明](../../../plugins/emuera/README.md)，不代表商业游戏、数字菜单或通用受管入口已通过。以下保留设计时的方案与验证门槛。

## 目标与已有证据

将固定 Emuera 1.824／.NET Framework 4.5 构建的自写场景接到现有 BridgeClient。原运行时 SHA-256 为 `a9af3d1e8b7eb4b9323faf6da6d770addf507e4fd2ee0eb5cfc2e58603fa58e6`。不把同名 EXE、Skia 或其他封装当作兼容版本。

只读反编译确认：`Program.Main` 在 STA 线程创建 `MainWindow` 并运行 WinForms 消息循环；输入框原有 `richTextBox1_KeyDown` 接收 Enter 后调用 `PressEnterKey`。程序路径来自 `Application.ExecutablePath`，脚本、配置和保存路径默认位于程序目录及 `sav` 等子目录。运行时不是可直接挂载 Unity／Electron 插件的工程。

独立桌面／Job 的自写场景探针已验证：输入框经 `WM_CHAR` 收到数字 `7`，Enter 后显示绿色 `PHASE 1 - ACCEPTED 7`，再次 Enter 显示橙色完成提示；三张图已读回。前台 HWND 前后相同，所用原 EXE 摘要一致。两个 Enter 的松键消息已投递，但 `keyup_consumption_confirmed=false`，没有目标消费确认，也没有统一协议或失联保护验收。

六个本机候选目录均可只读识别为 `emuera_candidate`；识别只要求 `CSV/FLAG.csv`、`ERB/` 和具有 `MZ` 开头的 `Emuera*.exe`，不是完整 PE／程序集或版本认证。结果保持 `adapter=null`、`control_verified=false`。

## 推荐方案与取舍

推荐固定构建的 **C# STA 启动器＋目标内只读输入观察器＋独立 Python／Job 宿主**。首轮仍只加载运行时和自写 CSV／ERB，不运行商业剧情，不修改原 EXE。

| 方案 | 收益与限制 | 取舍 |
|---|---|---|
| C# 启动器加载已核对程序集，在原 UI 线程运行原入口；观察实际输入分发，Python 宿主持有 Job 和保护期限 | 可观察目标收到的按下／松开；UI 卡住时独立宿主仍能回收。需要新增加载方式，必须先验证与原入口的兼容性 | 已采用，仅固定构建与自写工程 |
| 沿用外部 PostMessage 探针作为正式桥 | 不需目标内观察器，但投递成功和外部画面变化不能证明目标消费松键 | 不满足正式桥验收 |
| 替换为新版 Emuera／Skia 或改写原运行时 | 输入接口、保存格式和行为可能变化，超出固定构建范围 | 本轮不采用 |

新增加载器是本项目要求先审设计的架构变更。本设计提交后，在恢复工作时按用户继续指令实施；实际路径验证确认入口 EXE／ExeName 变成启动器，脚本与配置仍在同目录。自写保存夹具实际落在程序旁 `save01.sav`，不将早期静态分析中的 `sav` 子目录泛化到全部配置。

## 加载与观察的验证门槛

1. 用现有本机编译工具构建启动器，按 STA 运行固定程序集的原入口；不安装工具、不重编译反编译出的引擎。没有可用工具时报告阻碍。
2. 启动器和 EXE 放在同一自写工程目录。验证 `Application.ExecutablePath` 变化对 `Sys.ExeDir`、`ExeName`、配置、重启和依赖加载的影响，不假设反射加载与直接启动完全等价。不得在原入口设置 WinForms 默认值前创建控件。
3. 在原窗口创建后绑定唯一目标输入框，观察器只记录正常键盘事件及消息分发结果，不调用 `PressEnterKey`、任务完成、切换场景、保存／读取函数，也不直接改输入框文本。
4. 按下确认必须发生在原引擎处理完成之后；松开确认必须来自目标 UI 线程处理本请求的 `WM_KEYUP`／对应正常事件之后，不能仅凭消息过滤器的分发前观察、宿主投递返回值或清空软件按键集合。
5. WinForms 的键处理和 `SuppressKeyPress` 是否影响松开事件，需要用真实运行测试确定。若无法在该构建建立可靠的分发后确认，停止该路线并报告证据，不将较弱回执写成消费确认。
6. 观察活性来自目标 UI 线程。后台文件线程仍能写状态不代表 UI 存活。目标内部观察器可以报告输入事实，独立宿主才能负责目标卡死后的回收。

## 协议与首版范围

- 复用现有 v2 毫秒协议、文件通道、BridgeClient、DesktopProcess 和图像判据；首版只开放实际验证的确认与等待。`buttons` 只声明 `ok`，不声明未经验证的方向／取消能力。
- `pause_scope=input`、`simulation_pause=false`；观察序号、WinForms 定时器和消息次数不冒充游戏帧。暂停只停止合成输入。
- 普通动作必须真实消费按下、真实消费松开、取得操作后的有效新图，才计成功；已经消费但截图失败时保留消费事实，另报取图错误。
- 不支持的动作、错误会话／PID／路径、过期请求、暂停代次失配与重复命令按既有协议拒绝或去重；不自动重放输入。
- **数字菜单仍是明确缺口。** 探针中的数字 `7` 不包装成确认键。现有 v2 没有数字或文本动作，首版只验自写 `WAIT` 场景；不能因此声称常见 Emuera 数字菜单已可操作。后续若扩展数字／文本协议，须另行确定接口并同步共用控制层、MV/MZ、RGSS3 桥及相应测试，不混入本轮。

## 生命周期与故障保护

1. Python 宿主创建独立桌面／Job 和新会话；仅启动本次新建的运行副本，不附着老师正在手测的进程。
2. 等待原引擎就绪和首张有效图，初始暂停。黑／白或均匀无效首图后零动作，保持现有 99.9% 判据。
3. 显式恢复后按当前会话和请求身份发出 Enter；只有目标分发后确认和有效图齐备才发布成功回执。
4. 保护期限沿用相邻实验桥：15 秒启动、1.5 秒租约、1 秒活动停滞、3 秒取图、1 秒释放确认；控制文件共享冲突仅允许既有 100 毫秒内重试。重复暂停或持续读取错误不得刷新首次释放时刻。
5. 暂停、租约失效、控制文件持续错误、输入／截图故障均停止新输入并请求释放。未得到目标确认时独立宿主按原期限终止自有 Job；不依靠已卡住的 UI 线程自救。
6. 截图可能阻塞，沿用探针中的独立取图工作进程及超时回收方式；取图进程也由本批生命周期约束，不能留下无主进程。
7. 正常关闭先确认松键，再请求原窗口正常退出；独立宿主保留一秒回收上限。退出时的配置写入必须记录；不为等写盘延后原回收期限。

## 数据、来源与还原边界

运行副本、生成物、配置、`sav`、日志、缓存与临时目录全部放在 `<Emuera验证目录>/`；子进程 APPDATA／LOCALAPPDATA／TMP／TEMP 同样定向。独立桌面／Job 不隔离文件系统、注册表或网络，不据此宣称通用数据沙箱。

只复制固定运行时与已核对必要组件，使用自写 CSV／ERB，不携带原存档或商业资源。原目录只读，运行前后核对所用源文件摘要；不修改老师的游戏、存档或安全软件设置。测试产生的保存／配置变化登记位置、用途与恢复方法；失败现场保留。纯自写工程恢复方式为关闭本批 Job 后重新构造新批次，不能覆盖旧失败证据。

仓库只提交自有启动器、观察器、宿主、夹具和说明。反编译输出、原运行时与商业资源不提交、不打包；同目录其他版本的许可证不能替代固定构建的来源／许可核对。插件交付前补齐固定组件摘要和可确认的许可边界。

## 计划代码边界与验收顺序

预计新增 `plugins/emuera/` 的启动器／观察组件、Python 宿主与说明，及 `tests/test_emuera_bridge.py`、自写 CSV／ERB 夹具。共用协议和其他引擎桥不在首版修改范围；产品识别仍不开放通用受管启动。

按测试先行完成以下检查，缺组件必须明确跳过，不能算通过：

1. 固定摘要拒绝、原入口加载、路径与依赖兼容；初始暂停和有效首图，黑图后零动作。
2. Enter 进入原引擎推进自写场景，目标分发后确认按下／松开，按键为空；重复请求不重复推进。
3. 暂停时新观察、手动暂停、租约失效、错误绑定／代次／非法动作。
4. UI 卡死、取图阻塞／发布失败、观察停止、持续控制文件错误、退出时正在按键；独立宿主按原期限回收。
5. 已消费但取图失败、未确认释放叠加持续读错、重复暂停等组合失败路径。
6. 经自写场景的正常输入完成保存、同进程读取及新会话读取；桥状态不进入存档。首版不借此补造数字菜单动作。
7. 原文件摘要、回执与图像摘要、全部自有进程退出、来源许可记录及受影响回归。

只有完成这些实证，支持表才能登记“固定构建自写工程实验桥”。商业游戏、数字／文本菜单、其他版本、通用受管入口、长期运行和真人并发分别保留未验状态。覆盖事实见[支持表](../../ENGINE-COVERAGE.md)，本机范围见[盘点表](../../LOCAL-ENGINE-INVENTORY.md)。
