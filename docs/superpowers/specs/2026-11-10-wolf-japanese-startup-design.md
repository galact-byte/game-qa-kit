## 推荐范围

为 Wolf 增加显式选择、按构建启用的日文启动方式，复用本机既有 Locale Emulator；不安装工具、不改系统区域、不改全局 LE 配置、不提权。官方中文范例保持原启动方式。

该方案触及进程创建和插件加载顺序，已在本设计后获得老师继续实施的批准。授权覆盖本设计的受控区域设置接入与验收；不改变原有时限和写入边界。

## 启动约束与验收次序

1. 先从本机既有工具的实际实现或版本对应源码确认 API 签名、标志、错误返回以及能否返回仍挂起的目标句柄。不能自行猜测结构体或调用约定。
2. 先用本项目自有最小 x86 程序做受控实验，记录进程内实际代码页与资源名解码；不得直接用商业游戏尝试未知启动时序。
3. 游戏主线程必须在独立桌面创建、由本次 Job 持有，且在桥和写入守卫就绪前不得执行游戏入口。若存在区域设置引导阶段，须记录该阶段的真实文件／注册表副作用并验证限制仍成立；仅确认游戏主线程挂起不够。
4. 现有加载器校验共同宿主、PID、路径、会话和 Job 归属。新启动拓扑若改变父子关系，不得删除校验，必须通过等价的明确所有权绑定并覆盖拒绝分支。由具体 API 实证决定是否需要这一步。
5. 任何准备／加载／所有权／代码页检查失败均回收自有 Job；不回退到普通桌面、前台键鼠或无守卫运行。不得借全局配置启用管理员模式。
6. 最小启动实验通过后才建新的商业完整副本；不带原档及 MTool，不修改资源命名和内容。先验证标题地图正常加载及真实切项，再验证完整帧边界、暂停／租约／失败恢复，最后走 MCP。每项均保留动作后图像，不能仅凭成功回执。
7. 原目录、原保存通路保持只读，批次前后哈希；保留成功和失败证据、数据记录与还原方法，退出后回收运行副本。

## 边界与选择

- 本设计批准后授权的是上述受控接入和验收；不代表已确认本版本 Locale Emulator 可满足约束。
- 若原生 API 无法满足挂起、独立桌面和守卫顺序，记录具体调用证据并停止商业验收，不放宽边界。
- 不建议直接包装默认 `LEProc.exe` 命令：其现有配置不是挂起启动，当前也没有守卫先就绪的证据。
- 不建议重命名或改写资源以迁就 CP936：这会引入游戏资源变更，并不能证明其他 ANSI 路径正常。
- 不建议修改系统区域设置：影响范围超出测试副本。
- 不扩展统一 v1／INI 协议或其他引擎，不把商业构建标成已支持，不包含原档读写、战斗和全流程。
