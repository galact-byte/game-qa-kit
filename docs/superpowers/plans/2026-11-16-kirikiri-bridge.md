# KiriKiri 固定构建实验桥实施计划

> 设计：[已批准实验桥设计](../specs/2026-11-16-kirikiri-bridge-design.md)。老师已批准并要求连续执行。使用 executing-plans 在隔离工作树内完成，不设置逐任务人工关卡。

## 约束与接口

- 仅固定 SHA-256 的 2.32.2.426／x86、自写 TJS 工程，显式加载桥；不启动商业脚本，不复制原存档或插件。
- 源运行时和原存档只读、前后 SHA-256 校验；测试数据、临时目录和账本在本地验证专用目录，不将本机路径写入源码文档。
- 统一 v2 JSON 文件协议保持不变；不改其他引擎客户端。复用现有独立宿主监督循环和取图 worker，避免复制一整套期限／释放逻辑。
- 首图必须通过原 99.9% 纯色判据，之后才允许正常输入。15 秒启动、1.5 秒租约、1 秒活性／释放／关闭、3 秒取图、100 毫秒文件 I/O 上限保持不变。
- TJS 覆层只改变合成 Enter 的单参数查询，其他查询委托原函数并保留上下文；原事件处理器返回后才能记录消费。Timer tick 不解释为帧。
- 目标观察使用受限结构数据，宿主解析时不执行 TJS；统一客户端不接触目标内部格式。

## Task 1：建立真实红阶段和查询覆层

Produces：`tests/test_kirikiri_bridge.py`、`tests/kirikiri_fixture/startup.tjs`、`plugins/kirikiri/GameQaBridge.tjs`。

1. 编写固定运行时独立桌面集成测试，先以缺少桥的行为断言失败；记录红日志。
2. 在正常 onKeyDown/onKeyUp 中实测合成 Enter 查询为按下／松开，其余键和解绑后查询委托原方法。
3. 通过正常事件改变画面；处理器异常／卡住不得记录成功消费。
4. 若固定运行时无法可靠包装查询与事件，保留证据并停止，不升级到 DLL 注入。

验证：`python -B -X utf8 -W error::ResourceWarning -m unittest tests.test_kirikiri_bridge -v`，测试运行时通过显式环境变量提供；不向仓库分发运行时。

## Task 2：接入独立宿主和严格入口

Produces：`plugins/kirikiri/host.py`、内部受限数据编解码器；既有 Emuera Supervisor 增加默认值不变的引擎身份类属性。

1. 为新鲜会话、固定摘要、显式自写工程、目录／软链接边界和精确 PID／路径写失败测试。
2. 目标配置仅由宿主生成；命令仅允许 down/up/close，身份与输入去重在目标侧再次确认。
3. 子类复用现有 v2 接受、租约、暂停、截图、退出和独立释放期限；监督声明准确的引擎身份／摘要。
4. 初始暂停，成功首图后只声明 confirm/wait；错误后的消费事实保留。

验证：聚焦桥测试及现有 Emuera 监督器回归；公共 control.py 不改动。

## Task 3：真实边界、正常存读档和回收

1. 测确认、等待、去重、未知动作、旧代次／会话／过期请求、PID／路径绑定。
2. 测人工暂停、租约失效、持续读取错误、按下／松开处理器卡住、重复暂停不能延后释放期限、宿主终止／正常关闭。
3. 测纯黑／白／杂点首图零输入、动作后黑图、截图写入失败／卡住、状态发布失败。
4. 自写场景通过 Enter 正常保存 123、修改 999、同进程与新会话读取恢复 123；存档及恢复记录单独保留。
5. 前台句柄、原文件摘要、进程退出、截图／回执摘要全部回读，不以计时器或文件存在代替画面验证。

## Task 4：交付审查与记录

1. 运行受影响单元测试与真实桥边界测试；若修改共用监督器，运行 Emuera 真实回归。
2. 无可用子代理工具时单独自审完整变更，标注审查限制；问题先复现再修复。
3. 新增 README／SOURCES，更新覆盖表、静态记录、盘点、路线及 CHANGES。仅登记固定构建自写工程实验桥，商业／受管入口仍未覆盖。
4. 核查来源与许可：桥与夹具为自有代码，不分发运行时；固定私有构建 revision／再分发许可未核实必须保留声明。
5. 按既有授权提交、主分支快进、推送并回读远端；生成逐文件核对的源码 ZIP、SHA-256 清单和中断交接。
