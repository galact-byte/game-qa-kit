# 受限原生后台输入实施计划

> 批准依据：用户已批准 `docs/superpowers/specs/2026-11-11-native-input-design.md`。按 executing-plans 连续实施；常规任务之间不等待二次批准。

目标：固定 x86 SRPG Studio 构建的键盘后台输入通过统一 MCP，保持 v1 帧桥语义。v2 显式毫秒动作、输入暂停、观察序号。软件输入不影响用户前台，副本外文件和注册表写入继续拒绝。

工作区：E 盘任务目录内的 `feat/native-input` Git worktree。实验、构建和证据放 E 盘任务目录，不跟踪运行副本、个人路径或游戏资产。

## 1. 协议分派与 MCP（Red → Green）

- 新增 `tests/test_native_input.py` 的真实文件会话行为测试：v2 身份、能力、观察序号、时间、截图、超时、命令去重与暂停。
- 先确认缺少 v2 功能导致失败，再在 `gameqakit/control.py` 实施显式 v1/v2 分派。v1 不接受毫秒字段；v2 不接受帧字段或 click，不换算。
- MCP 仍用既有六个 control 工具，补充 schema 与描述。MV/MZ、RGSS3 增加拒绝 v2 时间字段的回归；现有协议仍为 v1。
- 验证：新测试及 `tests/test_control.py`，MV/MZ JS、RGSS3、Unity/Wolf/HSP/DuckStation 受影响回归。

## 2. 原生输入核心与宿主（Red → Green）

- 把已验证 DirectInput 逻辑整理为 `plugins/native_input/` 的 x86 源码；本地已有 EasyHook 源码构建依赖，由显式参数指定，不下载/安装驱动或服务。
- 映射绑定 PID、会话、映像摘要；启动先暂停；按下/松开与缓冲事件一致；暂停代次、租约过期由进程内看门狗处理。
- 只允许固定映像、受控副本；启动保护与运行保护复用已有源而不降低写入限制；进程树 Job Object 回收。
- 自有 x86 测试程序验证轮询/缓冲事件/暂停/断线/卡线程/非法命令/截图失败/宿主退出，测试日志与截图归档。

## 3. 加载器与统一 MCP 端到端

- 精确映像白名单、完整副本、独立会话、外部数据摘要、前后台写入保护、关闭回收与失败清理。
- 原生 mailbox 与 Python 客户端接通，截图采用既有后台采集，不宣称游戏帧推进。失败停手，不抢前台补操作。
- 通过真实 stdio MCP 执行固定菜单路线：标题 → 环境设置 → 返回；逐图核对，记录输入消费计数、前台采样、松键和进程退出。
- 整理实体并发入口；只有老师实际操作后的记录才记为该后端的实体并发验收。

## 4. 审计与交付

- 运行相称回归、检查未知版本/字段、旧命令/暂停代次、超时、非法截图等失败路径。
- 同步 README、ROADMAP、覆盖表、后台方案、变更记录与本地交接；只登记实测构建与路线，不把人工并发未测项写成通过。
- 每块验证后合入主线并提交推送；工作区、提交号、远端三路核对。
- 回滚为卸下新后端并新建旧版会话；v1 后端不变，不降级全局键鼠。
