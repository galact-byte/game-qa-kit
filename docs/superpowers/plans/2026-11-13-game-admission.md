# 通用游戏接入实施计划

> 使用 executing-plans 连续执行；用户已批准设计与持续推进，常规步骤不另行确认。

依据：`docs/superpowers/specs/2026-11-13-game-admission-design.md`。保持协议、期限、判图和保存边界不变；真人验收最后集中进行。隔离开发分支，独立开发块验证后合入 main 并推送。

## 交付顺序与验证

1. **接入核心**：新增 `admission.py` 的只读检查、稳定阻碍码、版本化准备摘要与摘要指纹；人工观察由现有 ProfileDialog 选择进程，新增配置自动避名且 QA 根目录必须明确。先测试未知构建、依赖缺失、链接／重叠／既有目录、摘要变化再实现。
2. **显式绑定**：新增 `game_session.py` 的 Binding。验证精确 PID、路径、心跳、会话；跨进程动作锁；查询／暂停不需动作所有权；解绑确认暂停松键；退出／失效不回退旧 profile。MCP 使用同一上下文，阻断旧桌面输入、恢复存档、按名终止及跨目录控制。先行为测试，再真实 JSON-RPC 验证。
3. **进程所有权**：新增可选桌面的 `OwnedProcess`，复用 desktop 的原生结构；创建者挂起创建 worker、不可继承外层 Job、worker 挂起创建宿主并独占内层 Job。先真实自有进程测试正常退出、创建者／worker 崩溃、分配失败及旁观进程存活，再迁入宿主。不得从 session.json 收养进程。
4. **固定原生后端**：插件内生命周期入口复用 prepare/native-host。摘要重验后准备，首图合法且真实暂停／松键后才 ready_paused；不自动恢复或执行菜单。请求标识持久化去重，准备／启动／停止串行，外部连接无停止能力。取消、启动失败、桥失败均保留证据，源与外部数据核对，未知运行变化保留。
5. **用户入口**：Qt 中增量增加“AI 后台接入”对话框：选择游戏和 QA 根→只读检查与阻碍→操作摘要→确认准备启动→暂停就绪／首图→结束。原人工页保留。线程内处理耗时任务，关闭须请求停止并回收 Job。CLI 提供 inspect/status/start（start 保持前台生命周期）；MCP 提供 prepare/start/status/bind/unbind/stop，共用业务层。
6. **其他已有后端逐项迁入**：Wolf、DuckStation、HSP、RPG Maker、Unity 分别核查准备流程、依赖、保存边界和现有真实样本。满足条件的实现插件内 session 工厂并以入口完成真机回归；不满足的返回具体条件和下一步，不包装 smoke 脚本、不扩白名单。不得以预留空类宣称迁入完成。
7. **收口**：全部受影响 Python 测试、MV/MZ JS 桥测试、原生生命周期测试、真实 MCP 输入／截图／暂停／停止，Qt 常规／窄／高 DPI 截图检查。更新 CHANGES、ROADMAP、MCP 文档、集中真人验收清单与本地证据索引。

## 单步反馈回路

- 每个独立行为先补会失败的测试，运行聚焦 unittest 到 RED；最小实现到 GREEN 后才继续。
- `python -W error::ResourceWarning -m unittest discover -s tests -v`
- `node --test tests/rpgmaker_bridge.test.js`
- `git diff --check`
- 日志与临时数据只放选定 QA 数据根；本机测试位于 E 盘专用目录。串行运行，定期检查剩余空间；只回收本轮明确可再生数据。

## 风险与不可伪造的结论

- 动作回执不等于画面变化；读取操作后图，记录确切样本及版本。
- 连接本身不发送输入；停止只能由创建者持有的进程句柄执行。暂停失败保留现场并回收自有 Job，不能将 disconnected 当已松键。
- 执行中目标失效、取消、陈旧 PID、摘要变化均不允许自动重试启动或退回桌面输入。
- 独立桌面不是完整沙箱。尚无样本／已核查保存边界的后端不启动商业游戏。
- roadmap 的新引擎、虚拟机、安全设置、下载、YOLO 等外部前置条件保持显式待办，不用删条目或放宽边界获得“全部完成”。
