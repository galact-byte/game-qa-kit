# TyranoScript 实验桥实施计划

> **For agentic workers:** 使用 executing-plans 在本会话串行实施；按测试先行执行，不重新询问已批准范围的实现许可。

**目标：** 为固定 Electron 7.1.2／TyranoScript Ver5 自写工程接入现有 BridgeClient，证明输入、操作后图像、释放确认与独立故障回收。

**架构：** Python 宿主持有 DesktopProcess／Job；Electron 主进程负责控制文件和真实输入，页内观察器只上报真实键盘事件与绘制进度。所有会话对象留在游戏存档对象图之外。

**技术：** Python 标准库、现有 gameqakit、Electron 内置模块；不安装新依赖。

**设计：** [已批准设计](../specs/2026-11-15-tyranoscript-bridge-design.md)，2026-11-15 用户明确批准并要求继续。

## 全局约束

- 只运行 E 盘新建自写工程；原游戏只读，不带原存档，不提供商业包改写器。
- 复用 v2 JSON 文件协议，仅 confirm、wait、resume；不修改共用协议或其他引擎桥。
- 15 秒启动、1.5 秒租约、1 秒停滞、3 秒截图、1 秒释放，文件共享冲突最多重试 100 毫秒。
- `pause_scope=input`、`simulation_pause=false`；不得将观察序号当帧数。
- 首张黑／白图拒绝且零动作；按原全图 99.9% 判据。
- 正常真实事件、释放确认及操作后的新画面齐备才成功；失败回执保留已经发生的消费事实。

## 审查重点

- 暂停和损坏文件同时发生时，首次释放期限不能被重复刷新。
- 重复编号、旧会话、暂停代次错误与非法字段均不能投递输入。
- 页面仍有绘制但释放确认缺失时，独立宿主仍须回收。
- 主线程停滞、渲染停滞、宿主退出各自必须回收自有 Job，不能误杀其他进程。
- 同进程与跨进程正常读档不能恢复历史桥状态或改变保存根目录。
