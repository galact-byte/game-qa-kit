# Emuera 固定构建实验桥实施计划

> 供本会话按 executing-plans 连续执行。设计依据：[正式桥设计](../specs/2026-11-15-emuera-bridge-design.md)。用户于恢复工作时要求继续，按此前提出的设计推进；实现限于固定构建、自写工程、确认与等待。

## 全局约束

- 不修改共用控制协议、其他引擎桥与产品受管入口。
- 不运行商业剧情；源运行时只读。临时副本、配置、存档、编译与证据全部位于验证专用目录。
- 固定原 EXE 摘要与设计一致。保留 15 秒启动、1.5 秒租约、1 秒 UI 活性、3 秒截图、1 秒释放与退出期限，首图 99.9% 判据。
- 目标处理器实际返回后才能确认消费。处理器重新订阅或嵌套消息循环不能绕过这一要求。

## Task 1：验证启动器与输入观察

1. 新增真实集成测试与自写 CSV／ERB；先运行测试确认因启动器缺失而失败。
2. 使用本机 .NET Framework 编译器构建 C# STA 启动器，原程序集通过原入口执行；观察器仅发送正常窗口按键消息并记录原处理器返回后的事实。
3. 验证程序路径、引擎路径、依赖、首图、确认推进、松键确认和无前台变化。无法建立可靠分发后确认则停止并记录。
4. 验证命令：`python -B -X utf8 -W error::ResourceWarning -m unittest tests.test_emuera_bridge -v`（需显式提供已核对组件目录）。

## Task 2：实现统一协议与独立回收

1. 增加初始暂停、有效新观察、去重、非法请求／绑定／代次／租约、人工暂停与错误后的回执测试，先红后绿。
2. 独立 Python 宿主实现既有 v2 文件协议与 DesktopProcess／Job；输入观察和取图分别独立监控，不让取图阻塞期限判断。
3. 增加 UI 卡死、取图卡住／发布失败、释放未确认、重复暂停与读错组合、退出长按测试。
4. 截图或回执失败保留已发生的消费事实；任何重试不重置首次释放期限。

## Task 3：存读档、来源与交付

1. 自写场景通过正常 Enter 完成存档、同进程与新会话读取；记录文件变化与恢复方法。
2. 新增插件 README／SOURCES，更新覆盖表、路线图及 CHANGES；保持商业剧情、数字菜单、其他版本、受管入口未验。
3. 运行受影响回归和真实桥全部边界检查；回读前后截图、摘要与进程回收状态。
4. 全分支自查，明确缺少独立审查模型的限制。形成源码快照、摘要清单与交接（含新会话开场话术），按既有授权提交推送并核对远端。

## 接口检查

Task 1 产出目标 UI 线程的身份、活性、输入消费与窗口句柄；Task 2 只用这些事实构造统一回执。Task 3 沿用同一自写场景完成存读档，不能新增数字动作或直接调用存读档函数。
