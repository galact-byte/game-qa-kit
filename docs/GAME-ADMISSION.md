# 将游戏接入 GameQA

如果只是手动玩游戏、截图和记录问题，正常打开游戏后，在主界面选择进程并开始盯屏即可。

如果希望 AI 在后台操作游戏，请使用主界面的「AI 后台接入」。它会检查所选游戏、说明缺少的组件，并为符合条件的游戏准备独立副本。当前支持范围见[引擎支持范围](ENGINE-COVERAGE.md)；识别出引擎不代表该游戏一定能后台操作。

## 开始之前

准备好以下内容：

- 游戏的 EXE 或所在目录。
- 用于存放测试副本和记录的文件夹，建议选择空间充足的非系统盘。
- 该游戏所需的运行时和控制组件。便携包包含 GameQA 自身运行环境，这些额外组件仍需另行准备；检查结果会说明具体缺项。

工具不会自动下载组件，也不会直接修改原游戏。原存档是否复制到测试副本，由具体适配方式决定，以确认前的操作摘要为准；部分目标从空白进度开始，部分目标需要复制进度或初始化数据。需要继续已有进度时，应先核对该游戏的保存位置和适配范围，不能把原存档目录直接作为测试目录。

## 在界面中接入

1. 打开「AI 后台接入」，填写「游戏目录」「QA 数据目录」，并在「后台组件目录」选择已有组件的位置。
2. 点击「只读检查」，查看缺项和下一步提示。检查通过后，界面会列出本次副本位置与拟执行的操作。
3. 点击「确认并启动」，阅读并确认本次操作摘要。工具会依次准备副本、启动游戏并等待首图；无需再点击独立的准备或启动按钮。
4. 等待界面显示暂停就绪并出现有效画面。启动本身不会自动执行游戏操作；让 AI 操作前，还需在它的 MCP 客户端明确绑定会话并恢复输入。
5. 测试结束，在创建该会话的窗口点击「结束会话」，等待进程退出和数据核对完成，再处理测试副本。

后台游戏的当前预览读取控制桥已发布的图片。打开观察窗口、刷新预览不会发送按键，也不会为了显示预览推进游戏。关闭连接者的观察窗口不会代替创建者结束游戏。

## 如何理解检查结果

| 结果 | 接下来怎么做 |
|---|---|
| 可以准备 | 确认目录和操作说明后创建测试副本 |
| 缺少组件 | 按提示选择已有的构建、加载器或运行时，再检查一次 |
| 已识别，但不能从这里启动 | 该引擎可能已有控制插件，但尚未接入统一启动流程；查阅[支持范围](ENGINE-COVERAGE.md) |
| 构建不匹配或保存位置未核查 | 停止自动接入，不能通过改文件名或换配置强行启动 |
| 未知引擎 | 仍可使用人工盯屏；后台操作需要单独适配 |

支持从工具直接准备和启动的范围，目前包括 RPG Maker MV／MZ、VX Ace、已登记的 Unity 版本、固定 SRPG Studio x86 构建和 Wolf 官方范例。Unity 需要匹配游戏采用的运行时与输入接口；Wolf 商业构建、HSP 和 DuckStation 仍使用各自的插件入口。完整条件以[引擎支持范围](ENGINE-COVERAGE.md)为准。

## 连接已有会话

选择保存会话的「QA 数据目录」，点击「查找会话」，在列表中选择记录，再点击「连接所选」。已有独立控制桥也可通过「选择外部桥…」连接。

GUI 连接已有会话时只观察、查询和请求暂停，不取得动作权或进程所有权。**结束游戏需要回到创建它的 GUI、MCP 或 CLI。** 「断开连接」不会结束别的创建者启动的游戏。MCP 的动作绑定另行明确确认。

GUI 切换目标不会替另一个正在运行的 AI 客户端切换目标。多个客户端同时使用时，每个客户端都需要明确连接；同一受管会话只允许一个动作客户端。不要同时通过旧桥目录入口控制同一游戏。

## 让 AI 使用后台会话

先按 [MCP 配置说明](MCP.md)连接客户端。可以由 GUI 准备并启动，再让 AI 查找、连接该会话；也可以让 AI 通过 `game_*` 工具完成检查、确认、准备和启动。

准备和启动前，AI 应说明目标游戏、测试目录、将加载的组件及数据处置方式，并取得确认。绑定成功后，统一使用 `control_*` 工具操作游戏；动作完成后必须查看新画面，不能只凭成功回执判断操作生效。

暂停需要等目标确认松键。它不代表所有后端都冻结游戏画面，也不代表能够直接在同一进程中切换真人手玩。需要人工操作时，使用正常游戏和只观察流程；原生输入后端应先结束受控副本。

## 退出与数据保留

- 原游戏、原存档和外部数据按后端规定记录并核对摘要；独立副本和独立桌面不等于完整系统沙箱。
- 正常结束会回收工具创建的进程，但不会把整个会话目录直接当缓存删除。新进度、无法解释的差异和失败现场会保留。
- 截图、日志和基线用于追溯本次测试。清理可再生副本前，应确认差异文件有备份并有还原记录。
- 创建者退出或异常终止时，受管进程会按生命周期约束回收。重新打开工具不会自动接管旧 PID 或恢复旧动作。

遇到黑图、画面无法确认更新、输入释放未确认或启动失败时，保留该会话的日志和截图，停止后续操作。不要通过反复恢复、延长限制或抢前台点击继续测试。
