# 游戏接入与受管会话

主程序保留人工盯屏，并增加“AI 后台接入”。这两条路径共用现有观察和证据工具。引擎识别、已验证控制通路、当前构建能否由新入口启动是三件不同的事；以检查结果和[引擎覆盖表](ENGINE-COVERAGE.md)为准。

## 人工盯屏

1. 正常打开游戏，在主程序新建配置并选择运行中的窗口。
2. 确认程序路径和 QA 数据目录；新配置自动避开已有名称。
3. 开始盯屏，自己玩游戏并标记疑点。

选择窗口不会加载插件、恢复窗口或向游戏发送输入。保存路径未知时保持未设置，不自动猜测。

## AI 后台接入

1. 在主程序打开“AI 后台接入”，选择原游戏目录、QA 数据目录及已有后台组件目录。
2. 点“只读检查”，阅读引擎证据、阻碍和本次操作摘要。检查不会启动游戏。
3. 条件成立后点“确认并启动”。程序在 QA 目录下创建新副本，原目录只读、不带原存档；初次就绪时暂停输入，并显示首图。
4. AI 通过 MCP 显式连接该会话，明确恢复后才执行动作。界面显示的“运行”指输入控制状态，不代表整个游戏仿真被暂停或恢复。
5. 从创建该会话的窗口点“结束会话”，或关闭创建者窗口。程序请求暂停松键，回收自有进程树并核对数据。

当前完整启动流程覆盖已登记哈希的 SRPG Studio x86 构建、Unity Mono／旧 Input 的《Taimashi》及新 Input System 的《OmaNeko-Seikatsu》构建、MV 1.6.1／MZ 1.8.0 SDK 空白工程，以及固定 VX Ace SDK＋RGSS301 组合。原生后端需已有 `native-host.exe` 与 `native-input.dll`；Unity 需已有匹配的 BepInEx 5、Doorstop 与 `GameQaBridge.dll`，新输入构建还需同次构建的 `GameQaInputSystem.dll`，组件目录形状见 [Unity 插件说明](../plugins/unity/README.md)。MV／MZ 选择已登记的完整 NW.js 运行时目录，见 [RPG Maker JS 接入](../plugins/rpgmaker_js/README.md)；VX Ace 选择已有已登记 `RGSS301.dll` 所在目录，见 [RGSS3 接入](../plugins/rgss3/README.md)。检查会核对已登记工程、程序和组件摘要，不自动下载或安装。

Unity 副本使用独立产品标识和空白进度，私有 LocalLow 目录通过目录联接落在本次 QA 会话内；结束时核对原目录、原保存目录和 PlayerPrefs，移除私有联接。Unity 的暂停只暂停桥输入，不暂停整个引擎仿真。新 Input System 固定构建首图是 Live2D 启动画面，持续观察自然到达标题后，正常点击可进入房间并推进对白；Qt 当前预览、观察者关闭后创建者存活与最终回收均已核对。Rewired／IL2CPP 仍须分别迁入，不能由这两个 Mono 构建推断其他样本可启动。

Unity 受管启动在原有 15 秒期限内保持输入暂停，逐个校验新观察序号的候选首图；纯黑或纯白候选图及对应状态保存在会话的 `startup-candidates/`，自然出现符合原判据的有效图后才公布 `ready_paused`。同一序号不重复放行，候选图刷新不延长期限；取消、目标退出、身份／保存路径异常、未暂停松键、取图错误或后端就绪后断开仍立即失败。初始化占位心跳可能先于后端加载，在原期限内等待后端和有效画面；身份与松键检查不等待首图。此等待不发送游戏输入，不提高期限或放宽判据；已经就绪后的观察故障仍按原规则停止。

MV／MZ 完整复制固定 SDK 工程与 NW.js，排除原工程 `save/`，改用随机副本标识、会话内浏览器数据目录与临时目录。初次就绪仅观察自然初始化的标题，保持暂停且不发送输入；显式恢复后才可正常开始游戏、移动和打开菜单。结束核对原工程、原运行时和原浏览器数据；新存档或运行变化保留。商业游戏、自定义插件及其他 SDK／NW.js 构建尚未迁入本入口。

VX Ace 完整复制固定 SDK，排除原存档，仅副本改用已登记 RGSS301 并在已核查 Main 前加载现有 Ruby 桥；PNG 使用引擎自带 Zlib 编码。初始暂停标题、正常开始、角色转向、菜单、Qt 当前预览、观察者关闭后创建者存活与最终回收已实证，原工程和 DLL 前后无差异。该 SDK 地图不可通行，不能据此宣称真实位移；存读档、商业游戏和其他 DLL 组合仍须另验。新存档只留在 QA 副本内，发生内容变化或清理失败时保留副本。原有适配器与控制工具保留，不能据识别成功宣称可启动任意游戏。

只回收数据核对通过且没有任何运行变化的可再生副本。出现存档、缓存或无法解释的变化时保留整个运行副本及清单，供复核。退出、取图或桥失败均不回退到前台键鼠。独立桌面或复制目录都不是文件系统沙箱。

## MCP 创建和连接

`game_inspect(path, artifacts, destination)` 只读检查；条件成立且指定全新 `destination` 时返回 `plan` 和摘要指纹。`artifacts` 是已有组件目录，不是安装指令。

| 工具 | 参数与行为 |
|---|---|
| `game_prepare` | `plan`、`request_id`、`confirm=true`；异步准备，创建者须保持连接 |
| `game_start` | `directory`、`request_id`、`fingerprint`、`confirm=true`；只启动本 MCP 创建且已准备的会话，初始暂停 |
| `game_status` | 可选 `directory`；查受管会话或本连接的绑定状态，包含是否可停止 |
| `game_bind` | 桥 `directory`、当前 `session_id`、`confirm=true`；校验精确 PID、程序路径、心跳与会话，不恢复输入 |
| `game_unbind` | 无参数；确认暂停松键或目标退出后解绑，不回退旧 profile |
| `game_stop` | 会话 `directory`、`request_id`、`confirm=true`；仅创建者可停止，异步等待最终状态 |

创建流程为检查 → 审阅摘要 → prepare → 查询 prepared → start → 查询 ready_paused。准备与启动使用不同请求编号；请求编号在同一 QA 父目录内须唯一。相同编号与内容只查询原结果，不能借重复请求重启或重新取得所有权。超时先查询原请求／命令，不能盲目重发。

已有 GUI 或另一 MCP 创建的会话可显式 bind；不需要伪造受管记录。连接者可查询与暂停，只有取得动作锁的客户端可以恢复或发动作。连接不授予进程停止权；应回创建者窗口结束。创建者退出会回收其会话，不能靠另一客户端连接延长进程生命周期。

绑定后使用原 `control_status`、`control_resume`、`control_action`、`control_result`、`control_pause`。原生 v2 使用 `duration_ms`，v1 桥使用 `frames`，不能换算或混用。后台绑定、绑定失效和解绑后的空目标均阻止旧桌面输入、存档恢复和按名终止工具绕过控制桥；重新使用人工 profile 需另建明确的人工工作流连接。

## CLI

```bash
python -m gameqakit.cli game inspect "<原游戏目录>" --artifacts "<后台组件目录>" --destination "<QA目录>/<新会话名>"
python -m gameqakit.cli game start "<原游戏目录>" --artifacts "<后台组件目录>" --destination "<QA目录>/<新会话名>" --fingerprint "<检查返回的指纹>" --confirm
python -m gameqakit.cli game status "<QA目录>/<会话名>"
```

`start` 持续运行以保持创建者生命周期，Ctrl+C 请求收尾；它不会打印 PID 后脱离运行。`status` 不收养落盘 PID，也不因查询获得停止权。

## 记录与恢复

每次新建独立会话目录。`approved-plan.json` 保存已确认摘要，`session.json` 保存生命周期状态，`profile.json` 供现有观察工具加载，`bridge/` 保存控制与图片证据，`cleanup.json` 及前后清单保存退出核查。QA 父目录的 `.admission-requests/` 保存请求去重和进程生命周期锁。

重新启动程序只可查询历史记录或显式连接仍有效的桥；历史记录不是可以重新启动或停止任意 PID 的凭证。创建者／worker 意外退出会通过 Job Object 回收自有后代；未经正常核对的记录显示 `interrupted_unverified`，不追认已正常清理。

## 目录记忆与连接已有会话

接入窗口在选择的 QA 父目录保存 `admission-preferences.json`，包含上次游戏与组件目录；程序配置区只记住该 QA 目录的位置。重新打开窗口会恢复这些选择，改变目录后仍须重新检查并确认，不自动启动。

在 QA 父目录点“查找会话”，从列表选择后点“连接所选”；也可点“选择外部桥…”直接选择现有桥目录。列表只检查直接子目录，最多显示 100 个记录、扫描 1000 项，不递归查找其他游戏目录。列表包含历史记录，连接时重新核对目标身份、会话及心跳；历史记录不代表目标仍然存活。

图形窗口连接已有会话时只观察和暂停，不占用 MCP 动作权，不能停止其他创建者的游戏。断开和关闭必须确认目标已暂停松键或已退出；失败则保留连接供排查。固定原生 v2 与声明持续观察图的 v1 桥（已迁入的 Unity 旧 Input／新 Input System、MV／MZ 及 VX Ace）按观察序号刷新当前画面，创建者和外部观察者共用该路径，连接失效后清除旧预览；未声明观察图的旧桥仅在已有首图时展示首图，不发送取图或恢复动作来推动游戏。图片先读入字节后解码，避免解码期间占用正在更新的图片文件；首图摘要与校验使用同一份字节。

真人并发输入体验集中留到最终验收，自动测试和菜单画面不能代替真人验收。[集中真人验收清单](GAME-ADMISSION-ACCEPTANCE.md)列出当前可验目标、日常操作步骤与待确认记录；其余后端的产品启动流程仍须逐项迁入。
