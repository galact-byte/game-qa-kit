# EasyRPG 自写样本预检与接入建议

## 状态

本轮完成 EasyRPG Player 0.8 两个本机构建的后台可行性预检，没有实现产品适配器。产品仍仅识别 RPG Maker 2000／2003，不开放其通用启动或 MCP 控制。

后续建议为在 EasyRPG 上游源码中加入独立输入源及消费回执，再按既有 v2 毫秒协议接入。该运行时构建与交付方式尚待用户批准；本轮不替换原 Player，也不启动商业游戏。

两个 Player 不视作同一构建。最终场景由引擎正常新游戏进入，按键通过原 SDL 输入链触发角色移动，没有直接改坐标、剧情或场景。

## 已验证结果

运行参数使用 `--new-game --no-rtp --no-audio --window --no-vsync --fps-limit 60 --engine rpg2k`，明确传入工程、配置及保存目录；子进程单独设置 `TMP`／`TEMP` 和 `SDL_RENDER_DRIVER=software`，不修改系统环境。

- 默认渲染首批只得到纯黑图，零输入停手，目标已回收。软件渲染在两个构建均取得连续有效画面。没有通过降低黑帧标准放行默认渲染。
- 窗口位于独立 Win32 Desktop，未最小化。最终四批实时消息测试中前台 HWND 前后均未变化，没有置前台、实体键鼠输入或实际光标移动；这不能替代真人并发确认。
- 离线回放分别确认第 360～419 帧的 60 条 `RIGHT` 被记录，截图角色左边界从 x=134 移至 x=390，后续连续图保持位置。早期场景包含上游可直接读取的 XML，最终实时测试另用仅二进制的 `fixture-03` 复验。
- 实时窗口消息不使用 `--replay-input`。只在首张有效图后向自有窗口投递右方向键 `WM_KEYDOWN`／`WM_KEYUP`。两份构建各两批，共四批通过实际位移、释放后位置稳定与正常关闭。每张截图为 512×384；最终批次中持键截图均为 x=254，释放完成后 x64 为 x=294、x86 为 x=326，并在下一张图保持一致。这些是截图像素，不是引擎坐标。
- 最终两批正常关闭后，原记录器分别给出 40／46 个连续按下帧；原样本文件和 Player 摘要复核结果见本地审计。

启动淡入会改变角色颜色亮度。探针定位自制角色时使用其色相关系和预期包围盒，不以某一张过渡图的精确 RGB 为常量。最初固定 RGB 导致的误判批次保留，不计为输入成功。

消息按下与松开之间包含一次同步截图，实测约 672／766 毫秒，不能把探针的 `sleep(0.5)` 宣称为严格 500 毫秒输入。这也是正式实现必须把输入计时与取图分离的原因。

## 尚缺的实时确认

官方回放文件按游戏逻辑帧读取，读到末尾会结束回放；不能据此宣称提供交互式 MCP 控制。录制文件只写存在按键的帧，没有显式的松键消费回执。

更关键的是，最终实时两批在请求关闭前 `consumed.log` 均为 0 字节；正常关闭后分别为 1,023 与 1,122 字节。当前源码路径使用缓冲输出，不能用退出后的记录为运行中的 MCP 命令实时确认消费。

窗口消息投递成功、游戏画面改变、释放后位置稳定和游戏线程确认释放是不同证据。现有探针只证明前三项，尚未实现正式回执、租约、暂停、断线释放或独立故障监督。尤其不能把不可移动或卡死时的静止画面判为已释放。

## 建议的正式方案（待批准）

首版只接自写 RM2K 场景，提供一个单独命名、单独登记摘要的 EasyRPG 源码构建，不修改已安装的两个 Player，也不把新构建等同于它们。复用现有统一 MCP／v2 毫秒动作及独立桌面、Job 和宿主监督，不新增前台后备路径。

在上游 `Input::Source` 接口加入专用输入源，把合成方向键合入正常输入更新；在游戏实际处理输入后发布按下／松开状态、请求编号、会话绑定和递增观察序号。所有游戏交互仍经过原输入逻辑。游戏线程不执行证据文件 I/O；输入计时、租约和取图监督由独立宿主执行。暂停只停止合成输入，不能宣称仿真暂停；帧号可以辅助观察，动作仍明确使用毫秒。

首版范围建议为右方向键与等待，足以闭合目前自写场景的移动和停止；其他方向、菜单、确认、鼠标和存读档按实际样本另验，不预先声明支持。输出工程、配置、保存、临时文件和证据固定到任务副本；独立桌面和路径重定向不是任意商业内容的写入沙箱。

离线回放保留为离线验证手段。直接窗口消息保留为可行性探针；当前缺乏游戏线程实时消费确认，不作为正式完成回执的依据。源码方案增加了编译与交付维护成本，但能明确实现目标侧确认，无需向原运行时注入或修改用户机器上的 Player。

### 接入前的验证清单

1. 先核对现有编译链和依赖，不自动安装或下载新软件；需要新增组件时列出实际缺项并申请批准。
2. 用新构建复验仅二进制的自写场景、暂停首图、显式恢复、正常位移与松开；游戏端回执与截图、记录三方一致。
3. 保留既有启动、租约、UI、释放和截图期限，不因启动或编译困难延长；暂停、过期、断线和重复请求均不得重新产生输入。
4. 输入计时不被截图阻塞。持键时发生黑图、取图失败、游戏退出或 UI 卡死，独立宿主按原期限回收；消费不确定时回执如实记录未确认。
5. 双会话隔离、准备后篡改拒启、源码 MCP、便携 worker 和原文件摘要分别核对。真人键鼠并发统一留到集中验收。
6. 交付前补全 EasyRPG Player／liblcf 及实际链接依赖的许可证、对应源码和构建清单。本轮源码头注明 Player 为 GPL-3.0-or-later、liblcf 为 MIT；Player 的对应源码要求不能仅靠一行致谢替代。不重分发来源未齐的工具附带 EXE。

这份建议不是已经通过的设计或构建清单。RPG Maker 2003、商业工程、RTP、音频、存读档、其他 Player 构建、长期稳定性及真人并发均未验。既有产品协议、适配器和发布包没有变化。
