# 后台窗口截图与消息代理

本功能在操作系统层绑定一个现有窗口，不注入游戏、不访问游戏内存、不修改游戏文件。截图和窗口消息不调用前台切换或系统鼠标输入。它与引擎插件控制是两条独立通路，窗口消息投递成功不代表游戏消费输入。

## 当前实证范围

| 目标 | 截图 | 鼠标消息 |
| --- | --- | --- |
| 独立诊断桌面的自写 Win32 窗口（源码与 Windows 便携 EXE） | 完整客户区、DPI 尺寸通过 | 源码覆盖点击后画面变化、长按、分段拖动、滚轮坐标及去重；冻结 MCP 复验点击实际消费、重复请求不重放与退出回收 |
| 明日方舟 B 服 PC 版，Unity，游戏 High IL、MCP Medium IL | 经本人 UAC 同意后，High IL 代理使用 PrintWindow 取得完整 1600×900 客户区 | 窗口未最小化、被遮挡且失焦时，返回按钮消息入队成功，画面仍停留在进驻总览；未通过后台点击验收 |

明日方舟不列入后台控制支持范围，不能用本通路承诺后台换人。截图前后可能有游戏动画，像素不同也不能证明按钮响应。本轮没有注入、改文件、切换前台或使用系统鼠标，也没有尝试领取产品、调整人员或配方。

实机批次后补充了发送端的 DPI 坐标上下文与慢速松开间隔，自写窗口回归通过；没有再向明日方舟发送输入，不能把后续自写窗口结果算作商业游戏复验。Windows.Graphics.Capture 和 SendMessage 未实现、未验，不对所有后台输入方式作不可行结论。

## MCP 工具

文档使用服务器注册名；客户端可能加 `gameqa_` 前缀。无需 profile 时，直接传 `hwnd` 或 `pid`。

| 工具 | 参数／返回 |
| --- | --- |
| `background_start` | `confirm=true`；指定 `hwnd`、`pid` 或 `profile`。只有 HWND 时解析 PID；只有 PID 时按该进程的完整路径定位唯一窗口；没有显式目标时使用当前 profile。`elevate=true` 为默认值，调用标准 UAC；`false` 只供同权限自写窗口测试。返回 `agent_pid` 与待就绪状态 |
| `background_status` | 无参数；查询 `running`、`ready`、绑定身份、`size`、`integrity_rids` 和后端。退出后保留 `agent_pid`、目标身份及 `exit_code`；非零退出或读取退出码失败时附 `error`。等待 `ready=true` 才进行截图／输入 |
| `background_capture` | 可选 `out`，必须为尚不存在的绝对 PNG 路径；省略时写到工具的默认截图目录，以返回的 `out` 为准。返回 `out`、`size`、`sha256`；PrintWindow 失败或黑图明确报错，不回退桌面截图 |
| `background_input` | `confirm=true`、`command_id`、`kind`、`cx`、`cy` 必填；坐标使用截图对应的目标客户区像素。返回 `messages_posted`；`game_responded=null`，响应必须另行观察 |
| `background_stop` | 无参数；停止当前 MCP 创建的代理，尝试向绑定窗口投递松开，不结束游戏。`release_posted` 仅表示消息投递，不能当作目标已读取松开 |

`background_input` 的具体参数：

- `kind="click"`：普通点击或长按，`hold_ms=600..10000`，默认 600。
- `kind="drag"`：`end_cx`、`end_cy` 为终点，`steps=2..12`，默认 6；按住左键并分段移动，结束或异常时尝试松开。
- `kind="wheel"`：`delta=-1200..1200` 且不可为零，默认 -120；代理把客户区坐标转换为 WM_MOUSEWHEEL 所需的屏幕坐标。
- `interval_ms=600..1000`，默认 600；动作间及拖动分段使用该间隔。点击按下到松开也至少 600ms。
- `command_id` 为 1–64 位字母、数字、下划线或短横线。同编号、同动作返回原结果；同编号换动作拒绝。超时后不要换编号重试；结果未知时先核对画面。去重只在当前代理存活期间有效，每个代理最多 512 个编号。

启动示例；将 HWND 替换为当前目标，窗口重建后不能复用旧句柄：

```json
{"hwnd":123456,"confirm":true}
```

调用 `background_start` 后，本人同意系统 UAC，再用 `background_status` 等待就绪。接着调用 `background_capture`，例如：

```json
{"out":"E:/GameQAData/first.png"}
```

只有已经验证会消费消息的窗口才适合继续 `background_input`。以下为自写窗口点击示例，不表示明日方舟支持：

```json
{"kind":"click","cx":80,"cy":90,"hold_ms":800,"command_id":"owned-window-001","confirm":true}
```

结束时调用 `background_stop`。MCP 退出或目标进程退出也会回收代理；不通过 UAC 时不启动代理。更新源码后需要重连 MCP；Windows 本地候选已验证冻结代理入口，尚未正式发布。

## 启动失败诊断

`background_start` 返回 `running=true, ready=false` 仅表示已异步启动，不表示代理初始化完成。若随后退出，`background_status` 会保留退出码、代理与目标身份；重复查询和停止后仍可回读，新启动清除上次诊断。

非提权代理持续排空 stderr，仅在当前 MCP 内存保留最后 16 KiB，并以 UTF-8 解码、替换无效字节；不新增日志落盘。提权代理仍只回传退出码及通用错误说明，不为诊断新增特权文件写入通道。错误中若出现“只允许同用户的启动进程和目标游戏”，应核查启动方、代理和目标的用户身份，不应绕过同用户 SID、管道 DACL 或创建者检查。

指定 Sandboxie 配置已有同箱截图记录，但未覆盖后台输入或所有沙箱配置；本次只改善启动失败回报，不表示新增 Sandboxie 通用支持。运行中的 MCP 不会自动加载新实现，更新后需正常重新连接。

## 权限与生命周期

- 提权使用 `ShellExecuteExW` 的 `runas`，不绕过 UAC、不安装服务、不修改安全设置。可能出现的 UAC 界面由本人操作，后台约束不意味着静默授权。
- 本机命名管道使用随机名称，DACL 只放行当前用户；连接时另核对客户端 PID 与启动它的 MCP 进程。客户端也核对代理 PID，不接受同用户的其他进程连接。
- 代理持有目标进程句柄，记录进程创建时间、程序路径和固定 HWND/PID；不跟随重启进程，不接受请求重新指定目标。
- 截图以 PNG 数据回传普通权限端，由普通权限端新建文件。代理不接受任意文件路径或任意执行命令。
- 目标最小化时明确拒绝，不恢复、不置顶；被遮挡且未最小化是本轮真实游戏验证状态。
- 代理监视父进程、目标存活和通信期限，失败后退出；不把消息投递当作游戏已消费或松开已确认。异常时不退回前台输入。

## 开发验证与限制

相关测试位于 `tests/test_background.py`、`tests/background_fixture.py` 与 `tests/test_background_integration.py`。窗口消息与截图可在独立诊断桌面验证。若 Windows 两次都拒绝读取系统光标，测试会单列跳过光标检查，不算作光标未移动的证据。要验证该项，请在可读取光标的活动桌面运行，测试期间不要移动鼠标或切换窗口；该项比较操作前后两个采样点，不是连续监测。测试覆盖截图、DPI、消息消费、长按与拖动、滚轮坐标、去重、其他进程拒绝、最小化拒绝，以及目标或父进程退出后的回收；入口测试覆盖工具注册、确认要求和非 Windows 隐藏。

固定自写窗口的冻结 MCP 已验证点击消费、同编号不重放及代理回收，商业游戏后台输入未通过。旧的 1280×720 商业游戏截图存在 DPI 虚拟化裁切，不能作为完整窗口证据；后续 1600×900 完整截图仍未显示按钮响应。自写窗口结果不能外推商业游戏。

冻结版本的自写窗口活动桌面隔离已完成补验。定位到 GUI 自检启动 MCP 控制台程序时新建终端窗口、短暂抢走前台；禁止该路径创建控制台窗口后，重建 EXE 的 182 次采样中光标与前台均未变化，后台点击只消费一次，三类退出回收通过。历史光标失败保留；该结果不代替商业游戏输入、真人并发或 VX Ace 心跳问题验收。原始截图、回执、批次日志和候选一致性记录仅在本地归档，不随源码分发。
