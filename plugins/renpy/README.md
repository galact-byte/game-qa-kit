# Ren'Py 固定自写样本接入

本目录提供 `GameQaBridge.rpy`，复用现有 v2 毫秒协议与 `BridgeClient`。通用游戏接入只支持已登记的 Ren'Py 8.3.2.24090902 本机运行时与本目录的自写场景，不分发运行时、商业资源或原存档。

## 从游戏接入启动

在“游戏目录”选择本目录下的 `samples/`，在“后台组件目录”选择已登记的运行时根目录（含 `Eternum.py`、`lib/`、`renpy/`）；可通过现有 GUI 或 MCP `game_inspect`、`game_prepare`、`game_start` 操作。普通 Ren'Py 游戏目录仍只识别，不可受管启动。登记核对整个 `lib/`、`renpy/` 的相对路径与文件摘要，以及原启动脚本；文件不一致时不启动。

启动时只复制登记文件到新的会话目录，零输入等待有效首图；确认绑定并显式恢复后才接受动作。停手时先确认松键，再回收独立桌面上的本次进程；黑屏会保留已消费的动作回执并停手。会话目录保留副本、截图和回执；旧会话不能重新作为源工程启动。

## 控制与观察

桥复用 Ren'Py 自带的键盘测试事件，把方向键、Return 和 Escape 交给引擎事件循环。它不发送系统键鼠输入；实验进程运行在独立 Win32 Desktop／Job 中。

- 动作包括 `move`、`confirm`、`cancel`、`wait`，每次 `duration_ms` 为 1–1000 的整数；不接受帧数，也不从回调次数推算逻辑帧。
- 默认输入暂停，显式恢复后才接受输入。`pause_scope=input`、`simulation_pause=false`：暂停合成输入时，游戏逻辑和预览仍继续。
- 使用引擎绘制结束回调检查测试事件队列；按下和松开均经事件循环消费后才确认。动作回执独立保留 `press_consumed`、`release_consumed`，等待与恢复不声称消费过输入。
- 预览按约 200 毫秒间隔更新，动作完成图单独保存；回执带截图 SHA-256。首张可用观察从项目的 `main_menu`／`start` 入口之后开始，避免将引擎自身的图形检查黑场当作项目画面。
- 连接明确校验协议、引擎、会话、PID 与 EXE 路径。暂停或租约失效时松键；无法确认释放时，在 1 秒释放期限后结束实验进程。释放期限由独立看门狗执行，重复暂停和持续控制文件读取失败不能延长首次释放时间。主线程停滞同样结束进程，不补写成功回执；启动期限为 15 秒，开始绘制后的停滞期限为 1 秒。
- 黑图、近乎全黑或全白画面及取图／发布失败会停手；已经消费的输入不会因截图失败改报未消费。Windows 文件共享冲突仅作 100 毫秒有界重试，超过期限仍按失败处理。

桥对象及运行中请求不进入 Ren'Py 的回滚／存档对象图。测试验证正常保存与读取后，桥会话和按键状态不会随游戏进度回滚。

## 验证方式

测试只运行自写工程，不加载商业资源。需要本机已有、匹配版本的复制运行时目录，其中包含 `renpy/`、`lib/` 与原启动脚本；当前夹具按 `Eternum.py` 这个已测脚本名启动，其他布局尚未验证。

```powershell
$env:TMP = '<E 盘测试临时目录>'
$env:TEMP = $env:TMP
$env:GAMEQAKIT_TEST_RENPY = '<已有复制运行时目录>'
$env:GAMEQAKIT_TEST_EVIDENCE = '<全新测试证据目录>'
python -B -X utf8 -W error::ResourceWarning -m unittest tests.test_renpy_bridge tests.test_renpy_managed -v
```

缺少 Windows 或未指定运行时时，真实运行测试明确跳过，不计为通过。证据目录保留状态、回执、截图、自写工程及引擎日志，不复制运行时。

测试将普通存档、游戏目录存档、跨游戏持久数据与存档签名密钥目录分别指向测试目录。仅重定向 AppData 不足以覆盖全部路径；这些设置只用于当前子进程和自写工程，不构成商业游戏的通用写入沙箱。

## 使用边界

仅支持这个已测运行时与标准引擎入口。鼠标点击虽有独立探针，尚未加入 v2 协议；不提供 `click`、持续跨命令保持按键或仿真暂停。现有共用协议和其他引擎桥未修改。

商业游戏脚本可能自行写文件、访问网络或注册表，也可能覆盖引擎回调；这些行为没有被独立桌面或桥隔离。商业启动与玩法、受管存读档、其他版本、长期稳定性与真人并发尚未验证。不要把此文件直接放入原游戏作为通用安装方式。回退接入提交可恢复原有只读识别，不迁移原游戏或存档。
