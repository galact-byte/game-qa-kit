## 使用边界

- 使用统一 MCP 的 `game_inspect`、`game_prepare`、`game_start`、`game_bind` 和 `control_*`。启动前必须先准备新副本，不直接控制原目录。
- 准备器只复制登记文件，排除原存档与附带诊断工具。由原启动器完成正常解包，仅替换最后一次启动播放器的调用以记录准备回执；播放器本体保持原始字节。输入／取图补丁安装在副本引擎中。
- 自有托管桥映射正常输入查询 `GetState`／`GetAxis`，区分按下、持续、重复与释放；不用 `ForceSetState` 同时伪造四种状态，不直接改位置、切场景或完成任务。
- 控制为协议 2 的 `duration_ms`，支持设计中的四方向、确认、取消和等待；实现中的能力标记不等于这些操作已在商业游戏验收。暂停只停止合成输入。
- 播放器运行在独立 Windows Desktop／Job 内，不激活用户桌面的窗口或移动真实光标。目录复制及独立桌面不提供文件系统沙箱。

## 组件与准备

合法持有的原游戏和登记组件须另行提供。组件目录必须包含 `GameQaKit.Bakin.PreparedLaunch.dll`、`GameQaKit.Bakin.RuntimeBridge.dll`、`GameQaKit.Bakin.PatchTool.exe` 与 `Mono.Cecil.dll`，摘要必须与登记清单完全一致；未知组件一律拒绝。第三方来源与许可见 [SOURCES.md](SOURCES.md)。

`build.py` 仅供维护者使用已有 .NET 编译器和已有 Mono.Cecil 构建自有组件，不下载依赖；构建输出的 `artifact-digests.json` 是待审查产物清单，不能自行授权新组件。修改源码并重新编译后，维护者须核对本地构建来源、测试和实际摘要，再同步登记并重新准备新会话。构建过程不要求最终用户安装编译器或编辑器。

准备采用独立 300 秒总期限；播放器启动采用本后端已批准的 60 秒总期限。初始化阶段的 Logo 和标题淡入不视为可控就绪；首图等正常标题交互态、输入／绘制活性和非最小化游戏主窗口。首图就绪后，1 秒停采样、1 秒释放确认、1.5 秒租约、3 秒截图、5 秒动作结果窗与 0.999 黑白图判据均保留。实际取图无效立即停止，不筛掉黑图再取一张。

新游戏加载使用已批准的显式生命周期：确认消费后撤销输入，仅暂停无持键时有界观察，普通释放及新地图截图审核均成立后仍保持暂停；普通动作和其他后端不获得加载例外。该分支已实现，但正式商业整链仍未通过。

后续 live-20 在启动阶段停止，零输入、未取得首张目标状态或截图；验收脚本替换状态文件失败与 `startup_timeout` 因果未定。桥初始化异常缺记录的问题已由真实 CLR 样本复现并补上 `target-startup.json`，CLR 20 项通过；`running` 仅表示桥已发布状态。启动诊断组件已登记并进入独立 live-21 冻结包，35 模块／4 组件预检一致；实机取得标题首图、running 和一次菜单下移的实际按下／释放与新图。上移前绑定失效，新游戏确认未发送；宿主读取 `bridge/status.json` 遇 Permission denied，停机普通释放未知，保留 `activity_timeout`／`cleanup_failed` 终态。离线确定性复现普通会话读句柄阻塞原子发布，复用已有共享读取后转绿；完整回归 878 项中 569 项执行通过、309 项按环境条件跳过，零失败，编排 14 项通过。修正后正式读取入口并发 1,000 写／6,168 读无错误；共享读取修正在后续 live-22 中已重新冻结并验证至标题双向控制、新游戏确认和普通释放；加载仍未通过，最新诊断组件后续随 live-23 登记并独立冻结，但该批次未进入加载。原件无变化、进程退出、副本已回收；实机完整因果、截图阻塞及正式加载／玩法仍未验通，不新增已验证兼容范围。

先撤销输入许可并取消队列，尽力取得正常查询释放回执，再关闭自有 Job 回收进程树。缺释放回执只能记为释放未知；进程退出不能替代普通查询确认。
