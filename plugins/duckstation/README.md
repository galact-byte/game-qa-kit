# DuckStation／PS1 控制桥

面向已核验 Windows x64 DuckStation 构建的实验插件，沿用协议 v1、INI 和统一 MCP 动作。原模拟器、镜像、配置和进度保持只读；只在独立 Win32 Desktop 的便携副本中加载。

当前版本锁定 EXE 的 SHA-256：`2ea09675202a6758992571a57971b1cd57fd6b0dfde4b808624698bf52efdd57`，对应源码 commit `bb4e9ac5e`。原生帧号、暂停／单步入口及数字手柄回读使用该构建的偏移，其他构建在准备和 DLL 初始化阶段拒绝，不能仅凭文件名替换。已测副本使用随模拟器提供的 SDL 3.4.20。

## 准备与验证

使用本机已有 MSVC x64，不自动安装依赖。输出、工作区和证据目录放项目外；工作区和证据目录必须不存在。

```bash
python plugins/duckstation/build.py --test-core --output "<项目外构建目录>/CoreTests.exe"
python plugins/duckstation/build.py --output "<项目外构建目录>/GameQaDuckStation.dll"
python plugins/duckstation/prepare.py --source <已有模拟器目录> --workspace <全新工作区> --game <已授权CUE镜像>
python tests/duckstation_smoke.py --workspace <准备好的工作区> --dll <构建的DLL> --out <全新证据目录> --steps tests/duckstation/protocol-menu.json --boot-wait 180 --safety --mcp
```

准备入口不复制原 settings、memcards、savestates 或用户配置；创建便携配置、独立空白记忆卡路径，禁用音频和自动恢复。BIOS 与镜像使用已有文件。测试脚本先挂起创建进程，写入精确路径、PID、随机会话和 INI 绑定后恢复，随后只向这个独立桌面进程加载 DLL。程序退出后由 Job Object 回收进程树。

`--boot-wait` 只是让开场自然运行的秒数，不是标题就绪检测。必须读回启动和菜单截图；动画、黑场或截图失效不能算通过，不放宽客户端画面校验。随附菜单脚本只适用于本次《妖精战士3》样本。

## 动作与证据

- 能力：`move`、`confirm`、`cancel`、`press`、`release`、`wait`，每次 1–120 帧。统一 `ok` 对应圆圈、`cancel` 对应叉、`shift` 对应 Start、`pageup/pagedown` 对应 L1/R1，`square` 对应方块；方向键正常映射。`square` 是可选按钮，统一客户端仅在插件状态 `buttons` 数组声明后接受，不改变其他引擎既有键位。没有坐标点击能力。
- SDL 虚拟手柄经模拟器正常绑定进入数字手柄。`native_buttons` 是 PS1 数字手柄按下位，`device_buttons` 是 SDL 回读位，`applied` 是桥已写入位；三个数的位编码不能混用。
- 时长按原生执行帧计数，不按 SDL 回调计数。执行请求帧数后释放，再推进两帧稳定状态并请求原生截图；普通动作的成功回执帧差因此为请求帧数加 2，包含截图对应的真实原生帧；首次恢复还包含接管自然运行到暂停之间的帧差，不按这个等式验收。
- 普通动作释放后两帧取图；首次截图若为黑帧，则保持松键，在原有 3 秒截图期限内每 30 个原生帧复查，不延长期限或降低黑帧标准。成功回执可能因此多推进观察帧，不能把总帧差全部当成长按时长。到期仍黑则原命令失败、暂停并释放；显式恢复后取得画面不能追认原失败命令为成功。
- 截图处理耗时不计入原生执行停滞：黑图处理结束后重新开始执行阶段的 1 秒计时，但 3 秒截图期限仍从首次请求开始。处理结束才返回的黑图或有效图片若已越过总期限，仍失败暂停。
- 原生单步在输入轮询线程调用；执行边界未推进、跳帧、帧号回退或未观察到输入均停止。SDL 在模拟器暂停时仍轮询，暂停与租约守卫继续运行，但不会增加游戏帧数。
- 回执含会话、命令编号、消费状态、执行帧和 PNG。消费仅证明模拟器读到了输入；菜单或玩法变化仍要读图核对。截图保存失败、超时或客户端拒绝黑场后停止后续动作。
- 优先暂停、旧会话拒绝、暂停代次、去重与租约沿用统一客户端。短暂读不到租约时保留最后有效的绝对截止时间，不延长它。暂停后须查询到连接有效、`paused=true`、`held=[]`，且原生与 SDL 按钮均为零。

通过现有 `control_status/control_action/control_result/control_pause/control_resume` 使用；不新增 PS1 专用 MCP。文件路径启动 MCP 的集成验证由 `--mcp` 执行，临时 profile 只绑定隔离副本。

原始 SDL 探针保留在 [tests/duckstation](../../tests/duckstation/README.md)。正式桥验收范围与证据见 [后台控制](../../docs/BACKGROUND-CONTROL.md)。本轮《妖精战士3》副本已验证正常剧情推进、屋内移动与往返、记录册保存及读取，并在重启后从测试卡读取、用 `square` 打开菜单、切换道具→装备和取消返回。证据见 `<PS1验证目录>/玩法验收索引.md`。后续首战实测从测试卡出发，通过正常输入出村、进入桥梁战斗，验证走格、战斗命令、行动结束切人、我方攻击／敌方回合、伤害与升级，并在清敌后推进战后对白、移动离桥返回世界地图；见 `<PS1验证目录>/battle-retest/战斗验证.md`。转场仍可能触发原 3 秒截图／默认 5 秒客户端超时，需安全暂停、按原编号查询并显式恢复；不代表全程无超时。音频、换盘、实体手柄干扰、其他构建和完整流程仍未验；实体手柄验证按当前需求跳过，保留现有接口，不阻塞基础适配收口。独立桌面不等于文件系统沙箱。
