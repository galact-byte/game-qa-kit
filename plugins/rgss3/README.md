# VX Ace 固定工程受管入口

本目录的 Ruby 桥沿用协议 v1／INI 与单帧正常输入。`prepare.py`、`session.py` 接入两种登记配置：SDK 空白工程＋既有 RGSS301，以及固定商业归档工程＋原配 RGSS300。商业配置核对完整资源、脚本表与 DLL 摘要；其他游戏、SDK 或 DLL 构建仍须独立核查，不能从引擎识别推断可启动。

## 选择与准备

- 原工程选择已登记的 SDK 工程目录，包含 `Game.exe`、`Game.ini`、`Data/Scripts.rvdata2` 和原 SDK 的 `System/RGSS300.dll`。
- 组件目录选择已有且匹配已登记 SHA-256 的 `RGSS301.dll` 所在目录；不下载或安装其他 DLL。该 SDK 仍使用本机既有的 RPGVXAce RTP 素材配置。
- QA 目录必须全新，并位于原工程和组件目录之外。
- Python 的脚本表读写依赖 `requirements.txt` 中的 `rubymarshal`；游戏进程内的 PNG 编码使用 RGSS301 自带 Zlib，不引入图像编码组件。

检查只读取文件；确认后只修改新副本。SDK 复制排除根目录的 `Save数字.rvdata2` 原存档，在副本配置中将库改为 RGSS301，复制现有 Ruby 桥，并在固定工程已核查的 Main 入口前加载桥。完整工程、DLL 和桥均参与摘要核对；工程或计划变化时拒绝继续。

商业配置选择已登记的 `Game.rgss3a` 工程，组件目录选原工程的 `System`。保留原配 `RGSS300.dll` 与 INI，在新副本解包 373 个条目并核对 175 段脚本的唯一实际入口后加载桥；越界、重复、损坏数据或目标冲突拒绝。仅登记过的 `Graphics/System/window.png` 保留松散文件优先顺序。原存档与 `system_data.rvdata2` 不带入；使用专用 1–7 号检查点需在 CLI／MCP 明确选择，9 号档始终排除。参数与确认流程见[接入说明](../../docs/GAME-ADMISSION.md#从专用测试检查点准备实验)。

## 观察与输入

启动使用独立 Win32 Desktop 和创建者持有的 Job。后台桥在游戏 Main 入口运行前，将 BGM、BGS、ME、SE 播放请求的音量固定为 0，默认静音；音高及播放位置等参数保留，状态中的 `audio_muted: true` 表示此策略已安装。此策略仅作用于受管副本，不改系统音量、原游戏配置或存档；未启用后台桥的手动游戏不受影响。其他引擎的音频策略须分别验证。

先自然初始化标题，保持输入暂停与松键，拿到有效引擎首图后才报告就绪；首图无效时停止，不自动恢复或发送输入。声明观察序号后，Qt 创建者和外部观察窗口按持续观察图显示当前画面。

图像编码、初始图与持续观察在游戏进程内完成。暂停仅暂停桥输入，游戏仿真和观察继续。动作仍受单帧输入能力限制；正常输入和截图证据经现有 MCP 通路处理。

## 保存与收尾

两个固定配置的正常存档写入副本根目录，原工程保持只读。停止先确认目标暂停、松键，再结束创建者的进程树，核对原工程和原组件摘要。仅副本逐文件内容与启动前基线完全一致且收尾核对通过时自动回收；出现新存档、其他运行变化或释放确认失败时保留副本及证据。

这不是任意脚本、文件系统、注册表或网络的沙箱。已核查保存边界只对两个固定配置成立，不接受额外脚本、插件或未登记 DLL。当前 SDK 地图为不可通行水面；其正常输入验收以开始游戏、角色转向和菜单为范围。商业配置已通过受管 MCP 正常读专用 1 号检查点、地图 26 从 `(15,10)` 移至 `(15,11)`、动作后暂停松键和停止退出；原件与检查点未变，副本因新生成 `system_data.rvdata2` 而保留。商业配置后续源码双受管会话 27 项通过，覆盖跨会话控制与停止隔离、创建者异常退出只回收自身、另一支继续移动和目标崩溃不虚报松键；Windows 冻结 MCP 的同一读档、移动和正常停止链路 14 项通过。Qt 玩法、冻结双实例故障回收和长期运行另验；详见[引擎覆盖](../../docs/ENGINE-COVERAGE.md)。
