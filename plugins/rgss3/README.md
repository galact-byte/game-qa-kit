# VX Ace 固定 SDK 受管入口

本目录的 Ruby 桥沿用协议 v1／INI 与单帧正常输入。`prepare.py`、`session.py` 将已登记的 VX Ace SDK 空白工程和既有 RGSS301.dll 接到主程序、CLI 与 MCP 共用的受管会话。商业游戏与其他 SDK／DLL 构建仍走独立核查，不能从引擎识别推断可启动。

## 选择与准备

- 原工程选择已登记的 SDK 工程目录，包含 `Game.exe`、`Game.ini`、`Data/Scripts.rvdata2` 和原 SDK 的 `System/RGSS300.dll`。
- 组件目录选择已有且匹配已登记 SHA-256 的 `RGSS301.dll` 所在目录；不下载或安装其他 DLL。该 SDK 仍使用本机既有的 RPGVXAce RTP 素材配置。
- QA 目录必须全新，并位于原工程和组件目录之外。
- Python 的脚本表读写依赖 `requirements.txt` 中的 `rubymarshal`；游戏进程内的 PNG 编码使用 RGSS301 自带 Zlib，不引入图像编码组件。

检查只读取文件；确认后只修改新副本。复制时排除根目录的 `Save数字.rvdata2` 原存档，在副本配置中将库改为 RGSS301，复制现有 Ruby 桥，并在固定工程已核查的 Main 入口前加载桥。完整工程、DLL 和桥均参与摘要核对；工程或计划变化时拒绝继续。

## 观察与输入

启动使用独立 Win32 Desktop 和创建者持有的 Job。先自然初始化标题，保持输入暂停与松键，拿到有效引擎首图后才报告就绪；首图无效时停止，不自动恢复或发送输入。声明观察序号后，Qt 创建者和外部观察窗口按持续观察图显示当前画面。

图像编码、初始图与持续观察在游戏进程内完成。暂停仅暂停桥输入，游戏仿真和观察继续。动作仍受单帧输入能力限制；正常输入和截图证据经现有 MCP 通路处理。

## 保存与收尾

固定 SDK 的正常存档写入副本根目录，原工程保持只读。停止先确认目标暂停、松键，再结束创建者的进程树，核对原工程和原组件摘要。仅副本逐文件内容与启动前基线完全一致且收尾核对通过时自动回收；出现新存档、其他运行变化或释放确认失败时保留副本及证据。

这不是任意脚本、文件系统、注册表或网络的沙箱。已核查保存边界只对固定 SDK 成立，不接受额外脚本、插件或未登记 DLL。当前 SDK 地图为不可通行水面；受管入口的正常输入验收以开始游戏、角色转向和菜单为范围，不能将其记为真实位移或存读档验收。既有商业副本的位移与读档实证另见 [引擎覆盖](../../docs/ENGINE-COVERAGE.md)。
