# Artemis 自写场景受管入口

只接 `samples/authored` 的原样自写场景，以及 `prepare.py` 登记 SHA-256 的本机 x64 运行程序与 `d3dcompiler_47.dll`。启动后先暂停输入并取得有效首图，再通过统一 MCP 显式恢复、右移或等待。场景用普通 `isDown(39)` 查询驱动色块；消费回执在该查询之后发布。

## 使用条件

在「AI 后台接入」选择本目录的 `samples/authored`，组件目录选择含登记 EXE 和 DLL 的已有目录，输出目录选择一个不存在的新位置。工具只复制这两个组件及自写场景，不复制商业脚本、资源或原存档。组件身份见 [来源清单](source-manifest.json)。样本内容改变、增加文件或使用其他运行程序都会被拒绝。

MCP 通过 `game_inspect`、`game_prepare`、`game_start` 启动后，先确认暂停首图，再以 `game_bind` 连接桥目录、`control_resume` 恢复输入。`control_action` 只接受向右的 `move` 和 `wait`；时长使用 `duration_ms`，单次上限 1,000 毫秒。等待不投递按键，暂停只停止合成输入，游戏继续运行。结束时由创建者调用 `game_stop` 并核对退出结果。

主便携包包含自有桥、样本和宿主，复用现有冻结 worker。EXE 和 DLL 须由使用者合法持有且摘要匹配，不随源码或主包分发；未知版本不能通过改名接入。许可边界见 [SOURCES.md](SOURCES.md)。

## 实现与故障处理

- Lua 在 `onEnterFrame` 与普通采样前检查命令期限、重申引擎输入覆盖；回调计数只用于诊断，不充当游戏帧。
- 宿主以目标发布的毫秒时钟设置有限租约和持键截止时间。心跳不能延长同一动作，暂停后必须显式恢复；旧会话、重复变更及过期命令不能重新按下。
- 双向文件均采用逐代只发布一次的记录。Windows 暂时不能打开尚未读入的新一代时，沿用当前已提交记录及其原期限；当前命令缺失、短读或无效会撤销输入。旧消费记录删除中的权限错误不刷新活性，也不阻塞新记录的读取。
- 沿用 1.5 秒租约、1 秒停帧／释放、3 秒截图、15 秒启动和 99.9% 黑白图判据。首图无效时零输入停止。目标停帧或 MCP 被强制结束时回收自有 Job；进程退出不等于目标已消费松键，未确认的释放如实记录。

保存与临时目录配置在会话副本中；结束复核自写源及源运行组件摘要。独立桌面不隔离任意文件系统、注册表、网络或外部保存位置，不构成完整沙箱。

## 实测范围

源码和便携 MCP 已验暂停首图、右移与正常消费、松键后两次等待位置稳定、重复动作不重放、人工暂停／恢复、过期请求拒绝、租约到期、双会话输入与回收隔离、截图故障释放、目标停帧及创建者中断回收。Lua 状态机的严格解析、短读、身份、重放、计时回绕和消费规则在固定引擎实际 Lua 运行时中执行验证。

另一次真实 MCP 动作的五帧生产截图为 x=80、84、90、98、98；每帧色块 2,501 像素，按下和释放分别有正常采样回执。143 次前台采样未见目标游戏占用用户前台，不能据此宣称真人键鼠并发验收。

历史首图偶发无效仍未归因，成功批次不代表已修复或启动绝无失败。商业入口与玩法、其他构建、其他方向、鼠标、菜单、存读档、音频、长期稳定性及真人并发均未验。详细历史见 [预检记录](../../docs/ARTEMIS-PREFLIGHT.md)和[接入设计](../../docs/ARTEMIS-ADMISSION-DESIGN.md)。

## 验证与回退

本地设置 `GAMEQAKIT_TEST_ARTEMIS_COMPONENTS` 指向登记组件目录，再运行：

```powershell
python -X utf8 -B -m unittest -v tests.test_artemis_bridge tests.test_artemis_lua tests.test_artemis_managed
```

设置 `GAMEQAKIT_TEST_PORTABLE_MCP` 为便携 `GameQA-MCP.exe` 可将受管用例切换到冻结入口。没有组件时，运行时用例明确跳过，跳过不算验证通过。

升级或回退宿主与 Lua 桥须同步，停止旧会话并重新准备目录，不复用旧代次文件。回退本次登记和插件即可恢复仅预检状态，无原游戏存档迁移；包含证据及新保存数据的副本单独保留。
